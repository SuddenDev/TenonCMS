# integral-cms

An embeddable CMS for Vite-based frameworks. It runs inside the host app (same repo, same deploy), with no separate service. Status: proof of concept. See README.md for the vision, usage and roadmap.

## Commands

- `pnpm dev:astro` / `dev:nuxt` / `dev:tanstack` / `dev:standalone`: build packages, then run the example (ports 4321 / 3000 / 3100 / 3200), the core watcher and the admin playground in parallel. Core changes reload in the example without a restart. The playground has HMR on `localhost:5173/admin/` and proxies `/api/cms` to the example (`CMS_URL`). The example's `/admin` uses the admin built at startup; `pnpm --filter @integral-cms/admin watch` rebuilds it on change (full reload)
- `pnpm build`: packages and all examples
- `pnpm typecheck`: runs `build:packages`, then typechecks all workspaces. Run it before calling work done. While a dev watcher runs, use `pnpm -r typecheck` instead (see Gotchas).
- `pnpm lint` (oxlint) / `pnpm fmt` (oxfmt): the husky pre-commit hook (`.husky/pre-commit`) runs lint-staged (`oxlint --fix`, then `oxfmt` on staged files); `pnpm install` enables it via `prepare`. oxfmt cannot format `.astro` and loads no Prettier plugins, so `fmt`, `fmt:check` and lint-staged run Prettier with `prettier-plugin-astro` on `*.astro` (`.prettierrc.json`). In `*.test.ts`, unused vars and expressions are allowed, because the type tests rely on them.
- `pnpm build:packages`: required after any change in `packages/*`, because examples consume `dist/`. Core builds first, then the admin writes into `packages/core/dist/admin`
- Core migrations are code in `packages/core/src/db/migrations/cms.ts`. Add a new key; never edit one that has shipped.
- `pnpm test`: Vitest in `packages/core` (`pnpm --filter integral-cms test:watch` to watch). For one test, run `npx vitest run <file> -t '<name>'` in `packages/core`; `pnpm ... test -- -t` does not filter. No build needed, tests import `src/`.

## Testing

- TDD, RED then GREEN: write a failing test first and run it to see it fail for the right reason. Then write the least code that makes it pass. A bug fix starts with a test that reproduces it.
- Unit tests live next to the code as `*.test.ts`, named after the file they test (`condition`, `build-data-schema`, `inference` for type-level tests, and the named population/query helpers), and cover pure functions. `src/tests/*.test.ts` is the integration suite, one file per area (`auth`, `writes`, `reads`, `refs`, `populate`, `on-delete`, `hooks`, `root-hooks`, `plugins`, `fields`, `presets`, `media`): a real `defineCms()` on `:memory:` libsql, driven through `createClient()` with a `fetch` that calls `cms.fetch` and keeps the session cookie. `src/tests/setup.ts` holds the shared schema, `fresh()` (instance, client and `fetchWithSession`), `relational()`, `seed()` and `withMedia()` (`local()` in a temp dir, 1 KB parts); `fixtures.ts` holds tiny images. Add HTTP behavior there.
- Examples and adapters are not tested yet. Verify them with the curl smoke test below.

## Architecture

- `packages/core` publishes as `integral-cms`. `src/index.ts` is only the export barrel; the public surface is what it lists. It has exports `.`, `./client`, `./register` (types only), `./presets`, `./plugins/redirects`, `./plugins/redirects/admin`, `./media/local`, `./media/s3`, `./media/ipx`, `./media/cloudflare`, `./media/default`, `./astro`, `./nuxt`, `./vite`, `./admin`, `./admin/vue`, `./admin/react`, `./preview`, `./preview/vue`, `./preview/react`. It is built with tsdown to `dist/`. `vue`, `react` and `react-dom` are optional peers used by the framework helpers, `vite` only by `./vite`, `aws4fetch` only by `./media/s3`. `image-size` (pure JS) and `ipx` (with sharp, for the default media) are dependencies; `ipx` is imported only by `./media/ipx` and `./media/default`.
  - Layout: feature-first modular monolith. `cms/` constructs instances and binds APIs; `collections/` and `globals/` own config, endpoints, operations and scoped local wrappers. `content/` owns shared pipelines. `auth/`, `media/`, `preview/`, `schema/`, `http/`, `client/`, `db/`, `plugins/`, `presets/`, `helpers/`, `admin/`, `integrations/` and `tests/` have distinct responsibilities. Root `index.ts` is the public barrel and `errors.ts` is browser-safe. Keep module READMEs and the four navigation examples in `src/README.md` current. Internal runtime code SHOULD import its owning leaf, rather than the package root.
  - `src/schema/index.ts` is the compatibility type barrel for fields, hook contracts, `inference/`, and feature config. Collection/global definitions live under their feature's `config/`; the identity helpers preserve literal fields and named hooks. `label`, `description` and `nav` are admin metadata. Drafts default to enabled, except media. `schema/config/types.ts` composes `Schema`; browser consumers MUST use type-only imports.
  - `src/schema/fields/` has one field type and validator per leaf. `index.ts` composes `Field`, `Fields`, `RefField` and `StoredField` as types; `field-schema.ts` dispatches validators. A group's validator is built recursively, and joins are not stored. `image`/`file` store media IDs and reuse relation validation. A slug follows `required` and `SLUG_PATTERN`; `readOnly` is an admin hint. `common.ts` owns `Common`/`Base`, and `image.ts` owns `Modifiers`/`ImageOptions`.
  - `src/schema/hooks/` holds contracts only. `Fn` uses method syntax so hook arguments are bivariant and typed collections remain assignable to `Collection`; inline wide fields get `any`. `Slot` is an array or named record. `HookData`/`HookDoc` give inline wide fields `any`. `HookArgs.cms` is the untyped `LocalApi` from `cms/api/local-api.ts`. Field, collection, global, root and media contracts retain their distinct stages. `runtime/run-hooks.ts` (`hookList()`, `runHooks()`) flattens slots and runs replacements in order; `undefined` keeps the prior value. `LocalApi.media` is optional.
  - `src/schema/inference/` is type-only, one file per concern (`common.ts` helpers, `data.ts`, `check-refs.ts`, `read.ts`, `options.ts`): stored `Data`/`Doc`, media read values, compile-time `CheckRefs`, `Resolve`, `Populate`, `Select`, `Read`/`ReadDoc`, `Checked` and `Exact`. `FilterKey` excludes groups, joins and many references. Selection keeps document IDs and only requested metadata; groups/globals have no document metadata. The `Wide` guard prevents recursion on untyped schemas. `Sub`/`Next` are the type-level counterparts of `step()` in `content/population/populate-plan.ts`. Preserve type tests in `inference.test.ts` and declaration-build checks.
  - `src/schema/validation/`: `check-schema.ts` checks relations, joins, conditions, unique placement, patterns, preview placeholders and depth at startup. `build-data-schema.ts` builds `dataSchema(fields, data)` per write because conditions depend on values; inactive fields retain type checks. `parse-data.ts` strips unknown keys and throws `ValidationError` by field path. Drafts use loose, type-only checks. Do not replace this with static startup compilation.
  - `src/schema/traversal/` owns one `eachField()` walker plus reference classification/paths, field lookup, filterability, inner fields and object/array mapping. Stored fields are visited in order; group children follow their parent, joins are skipped, and a visit returning `false` skips children. `schema/runtime/` applies defaults/slugs, custom validation (`validateFields()`) and field hooks (`runFieldHooks()`) through that walker. Custom validation skips inactive fields and children. Population, integrity and response selection/filtering share these traversal rules.
  - `src/helpers/` (barrel `index.ts`, re-exported from `.` and `./client`): `slugify.ts` (`slugify()`, `SLUG_PATTERN`; shared with the admin by relative import like `condition.ts`), `seo-meta.ts` (`seoMeta(doc, { general, seo })`: title with separator and site title, `noindex`, `canonical`, `image`, `verification` tags; the second argument is optional) and `breadcrumbs.ts` (`breadcrumbs()`, walks the resolved `parent` chain, no queries). Helpers MUST have no imports, so they run in the browser.
  - `src/presets/` (`integral-cms/presets`, barrel `index.ts`): one file per preset, `page.ts`, `seo.ts` (its group has `image`), `settings.ts` (`settings`: the `general` and `seo` globals, as `Global` objects with `nav.display: "settings"`) and `nested-paths.ts` (`nestedPaths()`). Plain field objects and named hook records; each file MUST stay readable without core internals, because it is the documentation of what a host gets. They import only `errors.ts`, `helpers/slugify.ts` and types, so no zod reaches browser bundles. Paths are stored by the `path` hook; `updateChildPaths` re-saves children with `cms.update(collection, id, {})`, so nothing read through `afterRead` is written back.
  - `src/cms/config/options.ts`: `CmsOptions`, `PopulateOptions`, `SettingsOptions` and the plugin, media and settings type math (`PluginCollections`, `PluginGlobals`, `MediaCollections`, `MediaOf`, `SettingsGlobals`, `ExactSettings`, `DefaultDepth`). `settings` (`false | { general?, seo? }`, each a `Global` or `false`) adds the default `general` and `seo` globals: `addSettings()` in `cms/config/add-settings.ts` runs after `mergePlugins()` and before `checkSchema()`, throws `duplicate global "<name>"` when a host or plugin global has a default's name, and without media strips `favicon` and `image` from the defaults (a replacement is taken as is). `SettingsGlobals<S>` is intersected into the instance's `globals`; like `MediaCollections` it is not distributive and counts `S = never` as omitted (TS2589 otherwise), and `ExactSettings<S>` maps unknown keys to `never`, because generic inference skips excess property checks. The instance type `T` already holds them, so `Cms<T>` passes `S = false`.
  - `src/cms/create-cms.ts` composes `defineCms()`, lazy DB/auth, defaults, optional media and HTTP. Config assembly merges plugins, settings and media before schema checks. `runtime/types.ts` holds `Core` (also `auth`, `getSession` and `localApi(scope)`), `Scope` (`perspective`: `published` | `drafts`) and `Inner`; `operation-context.ts` builds outer scopes (`outerScope(user, perspective)`) and binds the API hooks receive, and `transaction.ts` reuses the scope's transaction. `api/local-api.ts` is the untyped `LocalApi` contract (hooks, HTTP, plugins, preview get it as `cms`; each `*.local.ts` implements one method), `api/create-local-api.ts` assembles feature local wrappers and `withDrafts()`; `api/types.ts` carries public inference/JSDoc. `createInstance(user, perspective)` builds every instance and casts the untyped implementation once. `withDrafts()` and `withSession()` MUST keep their `<S>(this: S) => S` signatures to avoid TS2589. `withSession()` uses `auth/get-caller.ts`: draft reads need a valid session plus the preview cookie.
  - `src/content/` is the shared engine, not another public API. Feature local wrappers validate names/media restrictions/draft eligibility and bind the supplied scope; operations coordinate actions. `lifecycle/run-operation.ts` opens/reuses write transactions, runs collection operation hooks and invokes only outermost unexpected error hooks after rollback. Field/feature/plugin/root stage ordering stays intact; globals skip operation hooks. `writes/write-document.ts` runs defaults, slugs, beforeValidate, parse, custom validation, beforeChange, parse again, uniqueness/references, save, afterChange and afterRead. Draft saves skip custom validation, integrity and afterChange; publishing runs the full pipeline over pending data, while discard removes never-published documents through deletion effects. `reads/` loads, validates options, runs beforeRead, population, afterRead, media decoration and selection; afterOperation sees the selected result.
  - `src/content/population/` owns `PopulatePlan`, `toPopulatePlan()` and `step()` in `populate-plan.ts`, batched resolution in `populate.ts`, projection in `select-fields.ts` and validation in `validate-select.ts`. One query runs per reference/join field per hop, with target read hooks sharing the outer scope. Groups pass the plan through; joins require an explicit populate object. `pick()` preserves IDs, while `badSelectPath()` returns the first invalid path.
  - `src/content/integrity/` owns existing-ID/media checks, uniqueness, reverse reference discovery and deletion effects. `checkRefs()` rejects self/unknown IDs and checks file type/size. `checkUnique()` scans per unique field. `find-references.ts` shares one decoded object per owner; `apply-on-delete.ts` applies restrict, then set-null, then cascade after the row is deleted, in its transaction. Effect writes skip custom validation/reference checks while preserving hooks; cycles stop on already-deleted rows.
  - `src/media/` binds a scoped API in `api.ts`, config in `config/`, core/hook/read helpers in `runtime/`, feature routes in `endpoints/`, and actions in `operations/`. `operations/uploads/` owns create, put-part, complete, abort and local upload orchestration; expired rows are cleaned on create. Ownership checks return 404 for foreign/expired uploads. Completion assembles storage, validates size/image headers, writes the document with hooks and deletes the upload row in a transaction, then prerenders variants. `update.operation.ts` moves storage before DB writes and compensates on failure; folder renames report partial failures. Deletion commits the document/reference effects before storage cleanup and media afterDelete. Media uses `cms/runtime/transaction.ts` and shared content writers.
    - Media is on by default. `defineCms()` turns an omitted `media` or `media: true` into `defaultMedia()` (`local('./.uploads')`, `ipx({ prerender: true })`), imported from core's own export `integral-cms/media/default` (tsdown `external`, tsconfig `paths` and a vitest alias point it at the source). `./media/local`, `./media/ipx` and `./media/default` have a `workerd` condition that resolves to `media/workerd.ts`: `local()`, `ipx()` and `media: true` throw there, an omitted `media` is off. `media: false` is off everywhere. Image defaults: WebP, quality 85.
    - `url`, `src` and `srcset` are typed only on `MediaCollection` in `cms/config/options.ts`, not the stored schema. Intersecting the read result instead hits TS2589. `images/decorate.ts` computes these values, including field-level image options during population.
    - `variants/keys.ts` owns `.variants/<key>/<modifiers>`. Rendering, moving and deleting each have focused leaves. `operations/regenerate.operation.ts` exists only for providers with `render`; it removes obsolete variants and optionally prerenders missing ones. `library/names.ts` is browser-safe filename/folder/MIME logic; `library/names-in.ts` includes unfinished uploads in collision checks.
    - The `media` collection is reserved (host, plugin and route name). Generic local create/update/delete reject it through `collections/operations/local/check-writable.ts`. Media calls `content/writes/write-document.ts` and `remove-document.ts` directly; shared lifecycle hook collection returns no collection/plugin/root hooks for media.
    - Storage creation/moves precede database writes. Deletion removes the database document first, then storage. Preserve existing compensation, commit timing and cleanup behavior.
    - `cms_uploads` (migration `002_cms_uploads`) holds uploads in progress: it reserves the key (collisions count it) and binds the upload to its user (another user's part is 404).
    - Media documents live in `cms_documents`. Migration `003_cms_media_key` adds a partial unique index on `json_extract(data, '$.key')` for `collection = 'media'`. `db/queries/media/media-by-key.query.ts` repeats both literals so SQLite uses the index; the lookup key remains a parameter.
  - `src/preview/` separates browser exports/runtime from `server/resolve-url.ts`. `config/types.ts` owns config/messages/drafts/options; `templates/` has import-free placeholder parsing and resolution. Preview templates traverse groups and at most one non-many relation via `findById(..., { populate: false })`; preview functions get `{ cms }`. Collection/global preview-url endpoints are protected and `/schema` serializes configured preview to `true`. `runtime/store.ts` is the shared browser singleton used by Vue/React entries; preserve listener identity and idempotent cleanup. `runtime/preview.ts` accepts messages only from the expected parent/opener and configured admin origin, morphs saved pages with bundled idiomorph, and serializes/queues refreshes. `bind-elements.ts`, `merge-draft.ts` and `bars.ts` own DOM reporting, draft merge and session-gated bars. Browser entries MUST NOT import the server resolver, zod or CMS runtime. See the module README for protocol and mode details.
  - `src/plugins/`: `types.ts` owns `Plugin`, `RouteEnv` and `PublicRouteEnv`; `define-plugin.ts` preserves literals and `merge-plugins.ts` checks/merges schemas. Names MUST match `[a-z0-9-]` and MUST NOT be `auth`, `collections`, `globals`, `schema` or `media`. `http/` mounts named public/protected routes and collects middleware in plugin order. Public middleware/routes precede CSRF/session checks; plugin public writes MUST enforce their own protection. Protected plugins receive the session user and scoped CMS.
  - `src/plugins/<name>/index.ts` and `admin.ts`: bundled plugins, exported as `integral-cms/plugins/<name>` and `…/admin`. They import core by relative path but MUST only use what the public exports offer, so a third-party plugin can be written the same way. The admin half is plain DOM, because the host may not compile `.vue`, and styles its page with its own `admin.css`, imported as `?raw` and injected once (a `raw` plugin in `tsdown.config.ts` inlines such imports, because rolldown has none). It MUST NOT rely on Tailwind utilities; only the admin's `.input` / `.btn` are shared. `redirects/`: the `redirects` collection, a root `afterChange` that follows path changes of the listed collections (chains stay one hop), `POST /import`, public `GET /lookup`, `resolveRedirect(cms, path)` for host middleware, and a "Redirect tools" page.
  - `src/errors.ts`: `ValidationError` (`errors` by field path, HTTP 400) and `ConflictError` (restrict, HTTP 409), exported from `integral-cms`. It MUST have no imports, so browser code can import errors without zod.
  - `src/schema/condition.ts` owns `matchCondition()` and `Condition`, with no imports. The admin bundles it by relative path. Validation and runtime processing use it too; browser field contracts stay type-only so zod remains server-side.
  - `src/client/` is browser-safe: `index.ts` is the public barrel and augmentable `Register`; `types.ts` holds `Client`, registration and HTTP schema mappings; `create-client.ts` binds methods/uploads, `create-request.ts` binds fetch/origin and errors, and `query/read-query.ts` serializes options. `constants.ts` owns `API_BASE`. One configured client retains its own closures, upload retries/progress and cancellation. `Http`/`HttpFields` need their untyped-schema guards; `Collections`/`Globals` support Nuxt. Copied `register.d.ts` resolves `#integral/config`; unresolved aliases silently yield `any`, so preserve negative type assertions. Draft/preview/media methods match feature endpoints. The admin uses this same client.
  - `src/http/app.ts` (`createApp(core, site)`; routes get `Core`, and `c.var.cms` is the untyped `LocalApi`) mounts feature Hono sub-apps in exact order: CMS binding, public plugin middleware, auth and public reads; then CSRF, session, protected plugin middleware and protected routes. `read-request.ts` selects visibility/perspective, `query/` parses filters/populate/select using null-prototype trees, `strip-private-fields.ts` filters public responses after selection, and `parse-body.ts` keeps malformed generic JSON as `undefined` (media uses `{}`). Private fields cannot be public filters and are stripped recursively from populated results. Cookie/session read failures fall back to public; drafts require both preview cookie and session. `errors.ts` maps expected statuses and hides unexpected error messages. Inline typed routes belong in feature `endpoints/`; content validation stays in operations. Schema serialization lives in `schema/endpoints/read.endpoint.ts`, preview cookies in `preview/endpoints/`, auth/session in `auth/`.
  - `src/auth/config/build-options.ts`: `authOptions()` merges the host's `auth` options (better-auth's, without `modelName`) with core's. Core owns `database`, `basePath` and `secret`, forces `emailAndPassword.enabled`, and runs its `user.create.before` hook first: once a user exists, a request without a session cannot create users on any endpoint. Server calls without a request pass.
  - `src/db/`: `types.ts` holds fixed table/row contracts, `create-db.ts` opens Kysely, `adapters/libsql.ts` owns the driver and `map-document.ts` decodes metadata. `migrations/cms.ts` keeps shipped keys/bodies and the CMS migrator; `migrate.ts` runs it before better-auth migrations. Named `queries/` groups documents, globals, drafts, references and media around shared `document-sql.ts` expressions. Published reads see only published rows and `data`; draft reads see every row and `COALESCE(draft, data)`. Existing-ID checks count every row; uniqueness and reverse scans use published data. ID lists use one JSON parameter. Migration `004_cms_drafts` backfills publication from updated_at. Upload-table SQL still belongs to media operations/library during this migration.
  - Adapters generate no code. They alias `#integral/config` to the host's `integral.config.ts` and point the framework at runtime files that ship as `.ts` source in `dist/` (tsdown `copy`). The host's Vite or Nitro compiles them. `env.d.ts` stubs `#integral/config`, `#app` and `App.Locals` so core can typecheck them; it is not published.
  - `src/admin/`: hand-written `index.d.ts` for `integral-cms/admin` (it holds `Nav`, which the schema types import with `import type`) and `default.ts`, the stub `#integral/admin` resolves to when the host has no `integral.admin.ts`. Both are copied to `dist/admin` (with `entry.ts` and `virtual.d.ts`), where the admin's Vite build writes `index.js`. `vue.ts` and `react.ts` are tsdown entries: `renderVue(Component)` / `renderReact(Component)` wrap a host component into a `Mount` with reactive props and `update`.
  - Standalone admin page: `src/admin/entry.ts` mounts with `#integral/admin`; `html.ts` renders its script/CSS URLs. Shared adapter helpers are `path.ts` (validated path/alias), `favicon.ts` (host favicon/define), `input.ts` (client input/chunk) and `options.ts` (contracts). `#integral/admin-html` exports the page string (`virtual.d.ts`, referenced by `register.d.ts`). No host shell, CSS or JS loads on the admin page.
  - `src/integrations/vite/index.ts`: `integralAdmin()` for Vite frameworks without an adapter. Sets `ssr.external` for builds, aliases `#integral/admin`, adds the entry as a second `client` input, and serves `#integral/admin-html` (dev: `server.transformIndexHtml`, so framework preambles like React Refresh get in; build: from the client bundle, which builds before the server).
  - `src/integrations/astro/index.ts`: `injectRoute` for `/api/cms/[...path]` with `src/integrations/astro/route.ts` and, unless `admin: false`, `<path>/[...path]` with `src/integrations/astro/admin.astro` (reads the base from `Astro.routePattern`, imports `../admin/entry.ts`). `addMiddleware` with `src/integrations/astro/middleware.ts` (sets `locals.integral` to `cms.withSession(request)`, so the admin's preview renders drafts; prerendered pages and `/api/cms` get the plain instance), the Vite alias, `ssr.external`. Unless `preview: false` (an option only this adapter has), `injectScript('page', …)` starts the preview runtime with `morph: true` and `admin` (the validated path, or `false`) on every page; outside the admin's preview it shows at most the admin bar. `injectTypes` augments `App.Locals` and the client's `Register` with `typeof import(entry).default`; it is a string because Astro's API takes a string, and it MUST stay a module (`export {}`), or `declare module` replaces the client's types instead of augmenting them.
  - `src/integrations/nuxt/index.ts`: `nuxt.options.alias` (Nuxt forwards it to Nitro and to tsconfig `paths`), `build.transpile` for the runtime dir, `addServerHandler` for `/api/cms/**` with `runtime/server/handler.ts`, unless `admin: false`, a standalone `/admin` page: `dist/admin/entry.ts` is a second client Vite input, `runtime/server/admin.ts` returns the page from the Nitro virtual `#integral/admin-html` (dev: `@vite/client` + `/@fs` path; build: from `build:manifest`, where the entry is also deleted so Nuxt does not preload it on host pages), `addTypeTemplate` references `integral-cms/register` (app and Nitro contexts), `addImports` of `useIntegral` from `runtime/composables.ts` (`useAsyncData` around `createClient()`'s read methods; during SSR the client fetches through `event.fetch`, which forwards the request's headers (cookies too, so the drafts perspective works over HTTP), typed via `import type cms from '#integral/config'` and the client's `Collections` / `Globals`; `live()` merges the preview drafts into each `data` through a writable `computed`, and returns a new thenable, because Nuxt resolves the awaited result to its own object). `addPlugin` of `runtime/plugin.client.ts` (client only) calls `preview({ admin })` with `runtimeConfig.public.integral.admin` (the module sets it to the admin path or `false`). Adds the libsql native binaries to Nitro's `traceInclude`. `h3` is an optional peer because the handler imports it.
- `packages/admin` is `@integral-cms/admin` (private). ## Design decisions

- **One JSON documents table** for all collections. Schema changes need no migration. Filters use `json_extract`, and field names are checked against the schema before they reach SQL. SonicJS does the same.
- **Core owns the fixed tables only.** CMS migrations are hand-written Kysely code in the bundle, so they run without a filesystem (Cloudflare later). better-auth creates its own tables from the actual options, plugins included. All run lazily on the first DB access.
- **Kysely, own libsql dialect.** better-auth's `getMigrations()` only works with its Kysely adapter. `@libsql/kysely-libsql` pulls an older `@libsql/client` and a second native binary that the Nuxt build does not trace, so core has a small dialect over its own client.
- **Instance-owned server state.** Server state lives in the `defineCms()` closure, so several instances coexist. Browser preview deliberately shares one store across its framework entries.
- **Lazy DB and auth.** Nothing connects at import time. The secret is checked when auth is first used, so public pages keep working with a bad config.
- **The admin is a compiled library the host bundles.** Core never imports it, so headless is free. Extensions come from `integral.admin.ts`, compiled by the host's Vite with HMR.
- **Extension contract is `mount(el, ctx)` only.** No framework components cross the boundary, so the admin bundles its own Vue and hosts install nothing. Reactivity is by callbacks: `ctx.onChange` in, `update(ctx)` out. New admin slots MUST use `Mount<Ctx>` too. Admin helpers go into `ctx.integral` (`IntegralContext`: `base`, `navigate`), never at the top level of a context.
- **One published package.** Framework adapters are subpath exports with optional peer deps (`astro`, `@nuxt/kit`, `@nuxt/schema`, `h3`, and `vue` / `react` / `react-dom` for the admin helpers).
- **SQLite only for now**, through libsql (a file or Turso). D1 and Postgres come later, behind the same `documents` shape.
- **Admin path is an adapter option** (`admin: '/cms'`, default `/admin`), not part of `integral.config.ts`: routes are registered at build time, before the config can load. `adminPath()` in `src/admin/path.ts` validates it; the page passes it to the admin router as `data-base`. `/api/cms` (`API_BASE`) stays fixed.
- **Relation ids live in the document JSON.** A string, or a string array for `many`. Reverse lookups (joins, delete checks) scan with `json_extract` / `json_each`. Id lists go in as one JSON parameter (`IN (SELECT value FROM json_each(?))`), so there is no variable limit. Populate runs one query per field per hop.
- **Validation and hooks live in the local API.** HTTP is a thin layer, so server code, HTTP and the admin behave the same.
- **Writes run in one transaction** with their hooks, `onDelete` effects and nested calls. Nested calls MUST go through the hook's `cms`.
- **Presets are data, not features.** No `findByPath`: paths are stored and filtered like any field. The SEO title fallback is computed by `seoMeta()` at render time and never stored.
- **Reads are public, writes need a session.** Pages render the content anyway, and the Nuxt composable needs an HTTP read path for client-side navigation. Draft reads require a valid session plus the preview perspective cookie.
- **Private is an HTTP rule.** The local API, hooks and the admin see every field. `http/strip-private-fields.ts` strips private fields from public responses.
- **Options the admin evaluates MUST be JSON.** Conditions, built-in checks and plain defaults run in both places; `validate`, function defaults and hooks run on the server only.

## Gotchas (each cost a debugging round)

- Nitro rewrites `typeof window` to `"undefined"` as plain text, even inside strings. Keep browser-only code out of server bundles.
- libsql loads `@libsql/<platform>` with a dynamic require:
  - If Vite bundles core, the native binding breaks. That's why the Astro adapter and `integralAdmin()` set core as `ssr.external` in builds. Dev does not bundle, so it stays internal there and Vite reloads it.
  - Nitro's tracer misses the binary. That's why the Nuxt module adds `traceInclude`.
- `tsdown --watch` MUST run with `--no-clean`. Otherwise Nitro rebuilds while `dist/` is empty and logs ENOENT errors. Never run `build:packages` while the watcher runs: the core build deletes `dist/` (including `dist/admin`) under the watcher.
- `Object.assign(el, { dataset: ... })` throws: `dataset` is a getter. Use `setAttribute`.
- Nitro v3 (TanStack Start) traces the libsql binary on its own. Nitro 2 (Nuxt) does not.
- TanStack Start streams HTML. Use `grep -a` on curl output, or grep treats it as binary and prints nothing.
- `nuxt preview` runs with cwd `.output/`, so a relative `file:./cms.db` lands in the build output and gets wiped. Use absolute paths; the Nuxt example uses `resolve('cms.db')`.
- Astro 7 `astro dev` / `astro preview` run as daemons. Use `npx astro dev stop`, `npx astro preview logs`.
- `astro preview` does not load `.env`. The script runs it through `node --env-file-if-exists=.env`.
- `astro check` does not detect `@astrojs/check` under Astro 7. Use `astro sync && tsc --noEmit`.
- Nuxt: use `nuxt typecheck`. Plain `vue-tsc --noEmit` with Nuxt's reference-only tsconfig checks nothing.
- `tsc --noEmit` in the Astro example never checks `.astro` frontmatter. To test `App.Locals` typing, use a `.ts` file.
- Nuxt's `.nuxt/types/nitro-routes.d.ts` imports every server handler for `$fetch` route types, and that file belongs to the app tsconfig project. Server runtime files in a module MUST import from `h3`, not `#imports`, or the app project cannot resolve them.
- tsdown `copy` with a directory `from` nests the directory under `to`. Use the parent as `to`.
- A stale Astro daemon or leftover `cms.db` makes sign-up return 403 (first-user-only). Run `astro dev stop` and delete the DB before a smoke test.
- `:memory:` libsql has one connection. Code inside a transaction MUST use `trx` (`q(core, s)` in `cms/runtime/transaction.ts`), and hooks MUST call the `cms` they get, or the call blocks or fails with `TRANSACTION_ACTIVE`.
- `JSON.stringify` turns functions in arrays into `null`, so `/schema` strips `hooks` (a field named `hooks` stays, it has a `type`).
- A generic type parameter with a default (`C = {}`) gives context-sensitive functions in the argument that default as their contextual type, so their parameters are implicit `any`. `CmsOptions` intersects `collections` with a plain `Record<string, Collection>` inside `NoInfer` to give inline hooks a contextual type.
- Preset hooks type `data` as `any`. With `Record<string, any>`, a spread with a computed key (`{ ...data, [path]: x }`) is not assignable to a typed collection's `Data`. `collection` MUST stay optional in their argument type (`collection!` in the body); a required one is rejected by `CollectionHooks`.
- Query parsers (`parsePopulate()`, `parseSelect()`) build nested objects from raw query segments. They MUST use `Object.create(null)` nodes: on a plain `{}`, a `__proto__` segment returns `Object.prototype`, and the next write pollutes every object in the process.
- `tsc` colors its output in some shells, so `grep "error TS"` can match nothing and hide real errors. Use `tsc --noEmit --pretty false` when filtering.
- Generic inference skips excess property checks, so `populate` objects need `Exact` to reject unknown keys. For the same reason, type tests of field options use `satisfies Fields`, not `defineCollection()`.
- The recursive read types hit TS2589 on an untyped schema (`{ schema: Schema }`, the admin's client) without the `Wide` guard. `Http` / `HttpFields` in `client/types.ts` crash vue-tsc with a stack overflow there without their own `string extends keyof` guard.
- `ReadDoc` MUST stay `Simplify<Read<…, S> & SelectedMeta<S>>`, with `Wide` inside `Read`. `Wide<Cs> extends true ? … : Selected<Simplify<Resolve & Meta>, S>` hits TS2589 at `setup(defineCms(…))` in the tests (instantiation limit, with better-auth's types in the same statement), and `Selected<Simplify<Full & Meta>, S>` with `Wide` inside `Full` typechecks but makes tsdown's d.ts build run out of memory (`tsdown --watch` dies with it). Check both `pnpm typecheck` and `tsdown` after changing the read types.
- The client's `findOne` calls `client.find<K, O>(…)` with explicit type arguments; casting the result instead makes TS compare two deferred read types (TS2589). The Nuxt composable passes `options as never` on: TS cannot match its generic `Checked` to the client's, and its own parameter already checks the options.
- `keyof never` is every key, so `Exact<P, never>` would accept any object. `Exact` maps an object under a `true`-only key to `never`; that rejects an object on a relation `populate` does not resolve.
- An empty nested object is sent as the path itself over HTTP: `select: { parent: {} }` is `{ id }` locally but `true` (the whole value) over HTTP. Same for `populate`.
- A dangling relation id reads as `null` with the default populate. Tests that check stored ids MUST read with `populate: false`.
- Kysely 0.29 exports `Migrator` from `kysely/migration`, not from `kysely`.
- zsh: quote paths like `[slug].vue` in shell commands, or the glob silently matches nothing.
- tsdown d.ts output needs explicit types on the Nuxt module (`NuxtModule<Options>`). `@nuxt/schema` must be a peer, or its types get inlined.
- Nitro hook types (`nitro:config`) come from `import type {} from '@nuxt/nitro-server/augments'`.
- Hono `csrf()` only checks form-like content types. JSON requests are protected because browsers preflight them cross-origin and we send no CORS headers.
- TanStack Start throws `multiple entries detected` on a second client entry. `integralAdmin()` sets `isEntry = false` on the admin chunk in `generateBundle`, before Start's post hook reads it.
- `configureServer` also runs during `vite build` (TanStack/Nitro). Check `this.environment.config.command === 'serve'`, not whether a server exists.
- Dev servers bind `[::1]` and `curl localhost` hits them first. Test a production build on `HOST=127.0.0.1` and another port, with its own `DATABASE_URL`, or you test a leftover dev server and write into its DB.
- Browsers compile the HTML `pattern` attribute with the `v` flag, so the server does too. `<textarea>` ignores `pattern`.
- A leftover service worker on `localhost:3000` from another project can hijack navigation. If a page works in incognito but not normally, check DevTools → Application → Service workers.
- The admin's Tailwind scans only `packages/admin/src`. HTML that a host or plugin mount writes gets only the utilities the admin itself uses, plus `.input` / `.btn`. Use inline styles for the rest, or the class silently does nothing.
- `@ts-expect-error` covers the next line only. When oxfmt wraps a call over several lines, the directive MUST sit directly above the line with the invalid value, or `tsc` reports it unused plus the real error.
- A `defineCms({ ... } as never)` call infers `M = never`. A distributive or `[M] extends [MediaOptions]` conditional then hits TS2589; `MediaOf` checks `[M] extends [undefined]` and is applied to the return value, not inside `api()`.
- consola writes to `process.stderr`, not `console.error`. Tests that assert a log spy on `process.stderr.write`.
- shadcn-vue components import icons from `@lucide/vue` statically, which pulls every icon into the admin bundle and defeats `Icon.vue`'s lazy chunk. Generated components MUST use `Icon.vue` instead. The CLI also prepends a Google Fonts `@import` to `style.css`; remove it.
- IPX prefixes ids with `/` and treats a `getMeta()` of `undefined` as not found. The storage in `images/ipx.ts` strips the slash and returns `{}`.
- Without a session, a path that no public route matches answers 401 (the session middleware runs), not 404. Test "route missing" cases with a session.

```sh
  -d "{\"filename\":\"hero.png\",\"mimeType\":\"image/png\",\"size\":$S}" $B/api/cms/media/uploads | node -pe 'JSON.parse(require("fs").readFileSync(0)).id')
curl -s -b $J -X PUT -H "origin: http://$B" --data-binary @hero.png $B/api/cms/media/uploads/$ID/parts/1
curl -s -b $J -H 'content-type: application/json' -H "origin: http://$B" -d '{"parts":[]}' $B/api/cms/media/uploads/$ID/complete
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' $B/api/cms/media/files/hero.png
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' "$B/api/cms/media/img/f_webp&q_80/hero.png"
```

Expect 201, `{"etag":"1"}`, the media document with `width` / `height`, `200 image/png` and `200 image/webp`. Delete `.uploads/` with `cms.db`.

## Conventions

- TypeScript strict. Give each implementation file one main responsibility, usually one or two exported functions; keep related private helpers together. Use action role suffixes (`create.endpoint.ts`, `create.operation.ts`, `create.local.ts`, `find-documents.query.ts`) and kebab-case names. Keep entry barrels declarative, except framework-owned conventions. Do not split coherent pipelines just to meet a line limit or add forwarding layers without a responsibility.
- The local API validates every write with `parseData()`. Every write route MUST stay behind the session middleware. Read routes are public and MUST only accept field names that exist in the schema and that the caller can see (`private`).
- `src/schema/condition.ts` MUST stay free of imports; the admin bundles it.
- Admin UI: plain Vue SFCs with `<script setup>`, Tailwind classes, and the shared `.input` / `.btn` / `.btn-ghost` classes in `style.css`. Host inputs render in the admin's light DOM, so they can use those classes too.
- Versions in use: Astro 7, Nuxt 4.5 (nitropack 2, h3 v1), TanStack Start 1.168 (nitro 3 beta, React 19), Vite 8, TypeScript 6, better-auth 1.7, kysely 0.29, Hono 4, zod 4.
- never mention claude in commits
