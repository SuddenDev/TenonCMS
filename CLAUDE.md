# integral-cms

An embeddable CMS for Vite-based frameworks. It runs inside the host app (same repo, same deploy), with no separate service. Status: proof of concept. See README.md for the vision, usage and roadmap.

## Commands

- `pnpm dev:astro` / `dev:nuxt` / `dev:tanstack` / `dev:standalone`: build packages, then run the example (ports 4321 / 3000 / 3100 / 3200), the core watcher and the admin playground in parallel. Core changes reload in the example without a restart. The playground has HMR on `localhost:5173/admin/` and proxies `/api/cms` to the example (`CMS_URL`). The example's `/admin` uses the admin built at startup; `pnpm --filter @integral-cms/admin watch` rebuilds it on change (full reload)
- `pnpm build`: packages and all examples
- `pnpm typecheck`: runs `build:packages`, then typechecks all workspaces. Run it before calling work done. While a dev watcher runs, use `pnpm -r typecheck` instead (see Gotchas).
- `pnpm lint` (oxlint) / `pnpm fmt` (oxfmt): the husky pre-commit hook (`.husky/pre-commit`) runs lint-staged (`oxlint --fix`, then `oxfmt` on staged files); `pnpm install` enables it via `prepare`. oxfmt cannot format `.astro` and loads no Prettier plugins, so `fmt`, `fmt:check` and lint-staged run Prettier with `prettier-plugin-astro` on `*.astro` (`.prettierrc.json`). In `*.test.ts`, unused vars and expressions are allowed, because the type tests rely on them.
- `pnpm build:packages`: required after any change in `packages/*`, because examples consume `dist/`. Core builds first, then the admin writes into `packages/core/dist/admin`
- Core migrations are code in `packages/core/src/db/index.ts`. Add a new key; never edit one that has shipped.
- `pnpm test`: Vitest in `packages/core` (`pnpm --filter integral-cms test:watch` to watch). For one test, run `npx vitest run <file> -t '<name>'` in `packages/core`; `pnpm ... test -- -t` does not filter. No build needed, tests import `src/`.

## Testing

- TDD, RED then GREEN: write a failing test first and run it to see it fail for the right reason. Then write the least code that makes it pass. A bug fix starts with a test that reproduces it.
- Unit tests live next to the code as `*.test.ts`, named after the file they test (`condition`, `validate`, `types` for the type-level tests, `populate`, `query` for the query parsers), and cover pure functions. `src/tests/*.test.ts` is the integration suite, one file per area (`auth`, `writes`, `reads`, `refs`, `populate`, `on-delete`, `hooks`, `root-hooks`, `plugins`, `fields`, `presets`, `media`): a real `defineCms()` on `:memory:` libsql, driven through `createClient()` with a `fetch` that calls `cms.fetch` and keeps the session cookie. `src/tests/setup.ts` holds the shared schema, `fresh()` (instance, client and `fetchWithSession`), `relational()`, `seed()` and `withMedia()` (`local()` in a temp dir, 1 KB parts); `fixtures.ts` holds tiny images. Add HTTP behavior there.
- Examples and adapters are not tested yet. Verify them with the curl smoke test below.

## Architecture

- `packages/core` publishes as `integral-cms`. `src/index.ts` is only the export barrel; the public surface is what it lists. It has exports `.`, `./client`, `./register` (types only), `./presets`, `./plugins/redirects`, `./plugins/redirects/admin`, `./media/local`, `./media/s3`, `./media/ipx`, `./media/cloudflare`, `./media/default`, `./astro`, `./nuxt`, `./vite`, `./admin`, `./admin/vue`, `./admin/react`. It is built with tsdown to `dist/`. `vue`, `react` and `react-dom` are optional peers used only by the two helpers, `vite` only by `./vite`, `aws4fetch` only by `./media/s3`. `image-size` (pure JS) and `ipx` (with sharp, for the default media) are dependencies; `ipx` is imported only by `./media/ipx` and `./media/default`.
  - Layout: the `src/` root holds only `index.ts` (the barrel) and `errors.ts`. Every area is a folder with `index.ts` as its entry: `cms/` (`defineCms()` and the read and write pipeline), `schema/` (schema types, `fields/`, `hooks/`, validation, walkers), `http/`, `client/`, `db/`, `media/`, `plugins/`, `presets/`, `helpers/`, `admin/`, `integrations/` (`astro`, `nuxt`, `vite`) and `tests/`. New code goes into the folder of its area, not the root. `src/README.md` and each folder's `README.md` explain the files; update them when a file is added, moved or changes its role.
  - `src/schema/index.ts`: `Collection`, `Global` (both with `label`, `description` and `nav`, the admin's placement, which core never reads and `/schema` sends), `drafts` (default `true`; `media` is `false`), `Schema` and the `defineCollection()` / `defineGlobal()` identity helpers for `const` inference; they keep the literal `hooks` type, so a host can omit a record entry by name. It is the type barrel: it re-exports everything of `fields/`, `hooks/` and `types.ts`, so the rest of core and the admin import types from here only.
  - `src/schema/fields/`: one file per field type, each with its option type and its zod validator (`textSchema(field, on)` and so on; `on`: the condition matches, otherwise only the type is checked). `common.ts` holds `Common` (every field, joins too) and `Base` (stored fields). `index.ts` composes the `Field` union, `Fields`, `StoredField` and `fieldSchema()`, the dispatch by `type`. `group.ts` and `join.ts` have no validator: a group's is built by `dataSchema()`, a join is not stored. Browser code MUST import these types with `import type`, because the files import zod. A `slug` follows `required` like other fields; a value is checked against `SLUG_PATTERN`. `readOnly` is an admin hint only; core never reads it. `image.ts` / `file.ts` store media ids and reuse `relationSchema()`; `image.ts` also holds `Modifiers` and `ImageOptions`. `RefField` is `relation | image | file`.
  - `src/schema/hooks/`: the hook types, nothing that runs. `index.ts`: `Fn` (method syntax, so hook arguments are bivariant and a typed collection is still a `Collection`; with the wide `Fields`, inline in `defineCms`, they are `any`), `Slot` (array or named record), `Operation`, `LocalApi` (the untyped `cms` hooks get), `HookArgs`. `field.ts`: `FieldArgs`, `FieldHooks` (on every field but `join`), `Validate`. `collection.ts`: `CollectionHooks` and the write order. `global.ts`: `GlobalHooks`, a `Pick` of the collection stages. `root.ts`: `RootHooks`, `CollectionHooks<Fields>`. `run.ts` is the runtime: `list()` flattens a `Slot`, `runHooks(slot, key, value, args)` runs it in order and lets a hook replace the value under `key`. `media.ts`: `MediaHooks`, `MediaDoc`, `MediaRead`, `MediaApi` (the `cms.media` type; `LocalApi.media` is optional).
  - `src/schema/types.ts`: type inference only. `Data` / `Doc` (`FilterKey` keeps groups, joins and `many` relations out of `where`), `CheckRefs` (compile-time relation and join checks; an invalid `collection` or `on` maps to an `Invalid` type that names the allowed values), and the read types: `Resolve` types a populated read, `Populate` lists valid `populate` paths, `Select` the valid `select` keys for a populate spec (a wide `number` P, the `ReadOptions` constraint, allows every join; meta keys only where `Doc` is true, so not in groups and not in globals, which pass `Doc = false` through `ReadOptions` and `Checked`), `Selected` narrows a resolved type to the selected keys (`id` kept, plain records pass), `SelectOf` reads `O['select']`, `Exact` rejects extra keys (an object under a `true`-only key is `never`), `Checked` applies both to an options literal (`D` is the default depth, for `PopulateOf`), and `Wide` returns plain records for an untyped schema (the admin's). `Sub` / `Next` / `Off` are the type-level twins of `step()` in `populate.ts`. `Value` and `Select` dispatch on the field type into one small type per kind (`Targets`, `SelectGroup`, `SelectRelation`, `SelectJoin`); `CheckFields` into `CheckTarget` and `CheckOn`. `Keys<F, Match>` and `Replace<T, K, V>` are the two helpers everything else is built from.
  - `src/schema/validate.ts`: the startup checks and the validator of a write. `checkSchema(schema, populate)` runs at startup over collections then globals: relation targets exist, `required` + `set-null` and `cascade` in globals are rejected, joins only at the top level of collections and only on a relation that points back, conditions MUST name existing fields, `unique` only on top-level fields of allowed types in collections, every `pattern` compiles, `depth <= maxDepth`. `dataSchema(fields, data)` builds the zod object per write from each field's `fieldSchema()`, because conditions depend on the data (a field whose `condition` is false keeps only its type check); `parseData(fields, data)` runs it and throws `ValidationError` keyed by field path.
  - `src/schema/walk.ts`: runtime field walkers. `eachField(fields, data, visit)` visits every stored field with the object that holds it and recurses into a group whose value is an object (a visit that returns `false` skips the group's children). `fillSlugs()`, `applyDefaults()`, `runValidate()` (returns messages by path; skips a field whose condition is false, with its children) and `fieldHooks()` (a group's own hooks run before its fields') are loops over it. `isRef()` is true for `relation`, `image`, `file`; `targetOf()` is `'media'` for `image` / `file`, else `collection`. Every relation branch uses them, so images and files get checks, populate, `onDelete` and filters without a second copy. `relationPaths()` finds them at the top level and in groups, `fieldAt()` resolves a dot path, `filterable()` is the runtime twin of `FilterKey`. `innerFields(collections, field)` returns the fields a value continues with (a group's own, a relation's or join's target; `image` / `file` are leaves) and `mapValue(value, fn)` applies `fn` to a document or each document of an array; `strip()`, `pick()` and `badSelectPath()` recurse through both, so they share one shape.
  - `src/helpers/` (barrel `index.ts`, re-exported from `.` and `./client`): `slugify.ts` (`slugify()`, `SLUG_PATTERN`; shared with the admin by relative import like `condition.ts`), `seo-meta.ts` (`seoMeta(doc, { general, seo })`: title with separator and site title, `noindex`, `canonical`, `image`, `verification` tags; the second argument is optional) and `breadcrumbs.ts` (`breadcrumbs()`, walks the resolved `parent` chain, no queries). Helpers MUST have no imports, so they run in the browser.
  - `src/presets/` (`integral-cms/presets`, barrel `index.ts`): one file per preset, `page.ts`, `seo.ts` (its group has `image`), `settings.ts` (`settings`: the `general` and `seo` globals, as `Global` objects with `nav.display: "settings"`) and `nested-paths.ts` (`nestedPaths()`). Plain field objects and named hook records; each file MUST stay readable without core internals, because it is the documentation of what a host gets. They import only `errors.ts`, `helpers/slugify.ts` and types, so no zod reaches browser bundles. Paths are stored by the `path` hook; `updateChildPaths` re-saves children with `cms.update(collection, id, {})`, so nothing read through `afterRead` is written back.
  - `src/cms/options.ts`: `CmsOptions`, `PopulateConfig`, `SettingsOption` and the plugin and settings type math (`PluginCollections`, `PluginGlobals`, `SettingsGlobals`, `ExactSettings`, `DefaultDepth`). `settings` (`false | { general?, seo? }`, each a `Global` or `false`) adds the default `general` and `seo` globals: `addSettings()` in `cms/index.ts` runs after `mergePlugins()` and before `checkSchema()`, throws `duplicate global "<name>"` when a host or plugin global has a default's name, and without media strips `favicon` and `image` from the defaults (a replacement is taken as is). `SettingsGlobals<S>` is intersected into the instance's `globals`; like `MediaCollections` it is not distributive and counts `S = never` as omitted (TS2589 otherwise), and `ExactSettings<S>` maps unknown keys to `never`, because generic inference skips excess property checks. The instance type `T` already holds them, so `Cms<T>` passes `S = false`.
  - `src/cms/`: `index.ts` holds `defineCms({ collections, globals, plugins, populate, database, secret, auth, hooks, media })` returns the local API (`find`, `findOne`, `findById`, `create`, `update`, `delete`, `publish`, `discard`, `getGlobal`, `setGlobal`, `publishGlobal`, `discardGlobal`) plus `fetch(request)`. `cms.drafts()` returns the instance in the drafts perspective (`Scope.drafts`, passed to nested calls); `cms.forRequest(request)` returns it with the session user, and drafts only with the `integral-preview` cookie and a valid session (`caller()` in `http/middleware.ts`). Both are typed `<S>(this: S) => S` (and the internal `scoped()` builds them): a return type of `Api<T, D>` there hits TS2589 at `setup(defineCms(…))`. `cms.populate` holds `{ depth, maxDepth }` with defaults; its `depth` type is the config literal, which the client reads. `mergePlugins()` folds the plugins' collections and globals into the schema before `checkSchema()` (duplicate or invalid names throw), and the instance type `T` intersects the host's collections with the plugins' (`PluginCollections<PL>`, `unknown` without plugins). It builds one `Core` object (`scope.ts`: `schema`, `plugins`, `rootHooks`, `defaults`, `db()`, `bind()`); the other files are plain functions that take it first, so there is no closure to read through. `api.ts`: `bind(core, scope)` builds the local API for a `Scope` (`trx`, `user`, `context`, `nested`) as an untyped `LocalApi`; `api(user)` in `index.ts` casts it once to `Api<T, D>`, the typed interface in `api.ts` that carries the JSDoc, and the exported `cms` is `api(null)`. `scope.ts` also holds the shared helpers below. Internally a target is a `Name` (`{ kind, name }`, built with `col()` / `glob()`); `hookArgs()` turns it into the `collection` or `global` key hooks see. Every method checks the name with `known()` (an unknown collection or global throws; every method is `async`, so it rejects) and goes through `run()` (`run.ts`): `beforeOperation` / `afterOperation` (collections only), one transaction for writes (reused when `scope.trx` is set), and `afterError()` at the outermost call for unexpected errors. `inner(scope, trx, context)` builds the scope hooks get. `run()` keeps `args` untyped because `beforeOperation` MAY replace them. `slot(core, name, stage)` lists the hooks of a stage: the collection's or global's, then each plugin's, then the root hooks of `defineCms` (`RootHooks` is `CollectionHooks<Fields>`, every stage); `hookArgs(s, name, extra)` builds what every hook gets. Hooks get `cms: bind(inner scope)`, so nested calls share `trx` and `context`. `write.ts`: `write()` is the pipeline of `create`, `update` and `setGlobal` (validation runs twice, around `beforeChange`): `applyDefaults()` (create only), `fillSlugs()` (every write), field then collection `beforeValidate`, `parseData()`, `runValidate()`, `beforeChange`, `parseData()` again, `checkUnique()`, `checkRefs()`, the row write, `afterChange`, `afterRead`. `update` and `setGlobal` merge the input over the stored data (top-level keys, from the raw row, so read hooks never leak into it); with `effect` they skip id checks and `validate` for `onDelete` effects. With `{ draft: true }` (rejected by `draftable()` for `drafts: false`), `write()` stops after `beforeChange`: `parseData(…, loose)` checks types only (every condition treated as off), no `validate`, `unique`, `checkRefs` or `afterChange`, and the row's `draft` column is written (`insertDraft()` / `saveDraft()` / `saveGlobalDraft()`). `publish()` runs `write()` as an `update` / `setGlobal` with `{}` over the doc loaded in the drafts perspective, then clears `draft`; `discard()` clears it, or deletes a never-published document through `remove()`. Draft saves and publishes always load in the drafts perspective. Hooks get `draft` (`hookArgs()` defaults it to `false`; `run()` reads it from `args.draft`). `read.ts`: `read()` checks `where` keys and the `select` (`readSpec()` returns the populate `Spec` and the checked `SelectSpec`, or throws `Invalid select: <path>` before the query; `check*` functions throw, `bad*` functions return the first bad path), loads through `findDocs()`, then `readDocs()`: `beforeRead`, `populate()`, `afterRead` (field then collection), `pick()` last, so `afterOperation` sees the selected documents. `readGlobal()` uses `readSpec()` and `readDocs()` too. `remove()` in `write.ts` is the body of `delete`. SQL lives in `db/documents.ts`.
  - `src/cms/populate.ts`: the populate and select specs and what reads do with them. `Spec` (`false`, hops, or a path object), `SelectSpec`, `toSpec(options, depth)` (read options to a `Spec`), `step(spec, key, field)` (whether the key's value resolves, `on`, and the spec it continues with, `child`; the one place this arithmetic lives, including the group and join rules), `populate()` (resolves relations and joins in place, one query per field per hop, and runs the target collection's read hooks through `ReadHooks`), `pick()` (keeps `id` and the `select` keys; never throws), `badSelectPath()` (returns the first bad path; same resolution rules as `populate()`; `id`, `createdAt` and `updatedAt` only on documents, not in groups or globals).
  - `src/cms/refs.ts`: the integrity rules of the document graph. `checkRefs()` (ids MUST exist, no self-reference; throws `ValidationError`), `checkUnique()` (one scan per unique field per write; `Already used`), and `onDelete()`, which applies `onDelete` after the row is deleted: `references()` scans every relation to the collection (one query per relation field, a document with several matching fields shares one `data` object), `restrict` throws `ConflictError`, then `set-null` and `cascade` run through the `Effects` callbacks (the local API with hooks).
  - `src/media/` (see its README): the media library. `index.ts` is the entry: `MediaOptions`, `mediaCollection` (merged into the schema by `defineCms()` after `mergePlugins()`, before `checkSchema()`), `mediaApi()` (bound into `bind()` as `cms.media`). `core.ts`: `createMediaCore()` (→ `core.media`: storage, limits, image options, the `/img` allowlist, host hooks), `mediaOf()`, `runMediaHooks()` (host `media.hooks`, then plugins' `mediaHooks`), `read()`. `upload.ts`: `create` / `putPart` / `complete` / `abort`, cleanup of rows older than 24 h on each create, `upload()` for the local API. `library.ts`: `update()` (alt edits run `beforeChange` / `afterChange`; filename or folder changes move storage first, then the document, and move back on failure), `renameFolder()`, `removeMedia()` (document and `onDelete` in a transaction, then storage, then `afterDelete`), `folders()`, `namesIn()`. `variants.ts` owns the `.variants/` layout: render (prerender and `/img` share `renderVariant()`), move, delete, `regenerate()`. Media writes use `transaction()` from `cms/scope.ts` (the scope's transaction or a new one). `http.ts`: `mediaRoutes(core)` returns `reads` (`folders`, `files/*` with `Range`, `img/*` when the provider has `render`) and `writes` (uploads, `PATCH` / `DELETE /:id`, `folders/rename`), mounted at `/media` by `createApp()`. `names.ts` (no core imports): name rules, `freeName()`, `accepts()`. `images.ts`: `ImageProvider` (`render(key, modifiers, storage)`), `variantsFor()`, `allowlist()`, `modifierId()` (IPX syntax, sorted keys), `parseImgPath()`, `decorate()` (adds `url`, and `src` / `srcset` for images; `readDocs()` calls it for `find('media')`, `populate()` per field through `ReadHooks.media`). `storage/` and `images/` hold the adapters and providers, each its own tsdown entry.
    - Media is on by default. `defineCms()` turns an omitted `media` or `media: true` into `defaultMedia()` (`local('./.uploads')`, `ipx({ prerender: true })`), imported from core's own export `integral-cms/media/default` (tsdown `external`, tsconfig `paths` and a vitest alias point it at the source). `./media/local`, `./media/ipx` and `./media/default` have a `workerd` condition that resolves to `media/workerd.ts`: `local()`, `ipx()` and `media: true` throw there, an omitted `media` is off. `media: false` is off everywhere. Image defaults: WebP, quality 85.
    - `url`, `src` and `srcset` are typed on the `media` collection type only (`MediaCollection` in `cms/index.ts`), not in the stored schema. An intersection on the read result instead hits TS2589 in the tests.
    - Variants live under `.variants/<key>/<modifiers>`; `Storage.list(prefix)` finds a file's variants for moves, deletes and `regenerate()`. `regenerate()` (local API, `POST /media/:id/regenerate`, the admin's "Regenerate variants") exists only for providers with `render`: it deletes variants the options no longer produce and, with `prerender`, renders missing ones.
    - The `media` collection is reserved (host, plugin and route name). The local API's `create`, `update` and `delete` reject it (`writable()` in `cms/api.ts`); media code calls `write()` and `remove()` directly. `slot()` returns no collection or root hooks for it.
    - Order rule for every media operation: storage write first, then the database, then storage cleanup.
    - `cms_uploads` (migration `002_cms_uploads`) holds uploads in progress: it reserves the key (collisions count it) and binds the upload to its user (another user's part is 404).
    - Media documents live in `cms_documents`. Migration `003_cms_media_key` adds `cms_media_key_idx`, a partial unique index on `json_extract(data, '$.key')` for `collection = 'media'`. `mediaByKey()` in `db/documents.ts` repeats that expression as literal SQL, because SQLite ignores an expression index when the path or collection is a bound parameter (as in `findDocs()`).
  - `src/preview/` (see its README): live preview. `preview` on `Collection` / `Global` (`Preview` in `schema/index.ts`) is a template (`'/{category.slug}/{slug}'`) or a function `(doc, { cms }) => url | null`; the pages preset sets `'{path}'`. `checkSchema()` rejects a placeholder that is not a stored field through groups and at most one non-`many` relation. `template.ts` (`placeholders()`, `resolve()`: `null` when a value is missing or empty; no imports), `url.ts` (`previewUrl(entry, data, cms)`: one relation hop through `findById` with `populate: false`). `/schema` sends `preview: true` for either form (replacer in `http/index.ts`); `POST /collections/:name/preview-url` and `/globals/:name/preview-url` under `writes` return `{ url }`, 404 without `preview`; the client has `previewUrl()` / `previewGlobalUrl()`. `index.ts` is `integral-cms/preview`, the browser runtime (`edit()`, `preview()`, `subscribe()`, `getDrafts()`, `merge()`): no code at import time, no zod, no core runtime imports. It activates only when `window.name` starts with `integral-preview`, listens on `BroadcastChannel('integral-cms:preview')` and patches `[data-cms]` elements. With `preview({ morph: true })` (Astro), a `saved` message fetches `location.href`, morphs `<body>` with `idiomorph` and sets the title, then patches again; one fetch at a time, a `saved` during it queues one more. `idiomorph` is a devDependency, so tsdown bundles it into the preview chunk (`dist/preview-*.mjs`, shared with `vue` / `react`). `vue.ts` / `react.ts` (`integral-cms/preview/vue`, `/react`) hold `useDraft()`; they import `./index.ts`, so the built entries share one store.
  - `src/plugins/index.ts`: `Plugin` (`name`, `collections`, `globals`, `hooks`, `mediaHooks`, `routes`, `publicRoutes`, `middleware`, `publicMiddleware`), `definePlugin()` (identity, keeps literal types) and `mergePlugins()`. `RouteEnv` / `PublicRouteEnv` type the Hono sub-apps: `c.var.cms` is the local API (with the session user for `routes`), `c.var.user` only in `routes`. Names MUST match `[a-z0-9-]` and MUST NOT be `auth`, `collections`, `globals`, `schema` or `media`.
  - `src/plugins/<name>/index.ts` and `admin.ts`: bundled plugins, exported as `integral-cms/plugins/<name>` and `…/admin`. They import core by relative path but MUST only use what the public exports offer, so a third-party plugin can be written the same way. The admin half is plain DOM, because the host may not compile `.vue`, and styles its page with its own `admin.css`, imported as `?raw` and injected once (a `raw` plugin in `tsdown.config.ts` inlines such imports, because rolldown has none). It MUST NOT rely on Tailwind utilities; only the admin's `.input` / `.btn` are shared. `redirects/`: the `redirects` collection, a root `afterChange` that follows path changes of the listed collections (chains stay one hop), `POST /import`, public `GET /lookup`, `resolveRedirect(cms, path)` for host middleware, and a "Redirect tools" page.
  - `src/errors.ts`: `ValidationError` (`errors` by field path, HTTP 400) and `ConflictError` (restrict, HTTP 409), exported from `integral-cms`. It MUST have no imports, so browser code can import errors without zod.
  - `src/schema/condition.ts`: `matchCondition()` and the `Condition` type. It MUST have no imports: the admin imports it by relative path and bundles it, like `client.ts`. `validate.ts` and `walk.ts` import it. zod lives in `validate.ts` and `fields/*.ts`; the admin imports field types with `import type`, so zod never reaches it.
  - `src/client/index.ts`: `createClient()`, a typed HTTP client for `/api/cms` with the local API's method names. `Client<C>` is the interface with the JSDoc and generics; the implementation is untyped and cast once, like `bind()` in `cms.ts`. It owns `API_BASE`; core imports it from here, because the file has no runtime dependencies. Imports types only, so it is safe in the browser. Its types come from the `Register` interface; a type argument overrides it. `src/client/register.d.ts` (copied to `dist`) augments it with the type of `#integral/config`'s default export. If that alias does not resolve, `cms` is silently `any`, so test typing with `@ts-expect-error`. Keep it in sync with the routes in `http/index.ts`. `Http` / `HttpFields` map the schema to what HTTP sends (private fields optional), also for populated targets; they skip untyped schemas, where the recursion would not terminate. `Collections<C>` / `Globals<C>` export that mapping for the Nuxt composable. `readQuery()` sends `populate` and `select` through `paths()`; `select: {}` goes out as `select=`. `request(path, { method, body, query })` calls any route under `/api/cms`, for plugin pages. `client.preview.enter()` / `exit()` call `/preview`. `createDraft`, `updateDraft`, `publish`, `discard` (`null` when it deleted), `setGlobalDraft`, `publishGlobal`, `discardGlobal` call the draft routes. `client.media`: `upload(file, { folder, onProgress, signal })` (create, parts 4 at a time with 3 retries, complete; `DELETE` on failure or abort), `update`, `renameFolder`, `delete`, `folders`. The admin uses it too (`packages/admin/src/shared/api.ts`), so it is the only HTTP client.

## Design decisions

- **One JSON documents table** for all collections. Schema changes need no migration. Filters use `json_extract`, and field names are checked against the schema before they reach SQL. SonicJS does the same.
- **Core owns the fixed tables only.** CMS migrations are hand-written Kysely code in the bundle, so they run without a filesystem (Cloudflare later). better-auth creates its own tables from the actual options, plugins included. All run lazily on the first DB access.
- **Kysely, own libsql dialect.** better-auth's `getMigrations()` only works with its Kysely adapter. `@libsql/kysely-libsql` pulls an older `@libsql/client` and a second native binary that the Nuxt build does not trace, so core has a small dialect over its own client.
- **No module-level state.** Everything lives in the `defineCms()` closure, so several instances can coexist.
- **Lazy DB and auth.** Nothing connects at import time. The secret is checked when auth is first used, so public pages keep working with a bad config.
- **The admin is a compiled library the host bundles.** Core never imports it, so headless is free. Extensions come from `integral.admin.ts`, compiled by the host's Vite with HMR.
- **Extension contract is `mount(el, ctx)` only.** No framework components cross the boundary, so the admin bundles its own Vue and hosts install nothing. Reactivity is by callbacks: `ctx.onChange` in, `update(ctx)` out. New admin slots MUST use `Mount<Ctx>` too. Admin helpers go into `ctx.integral` (`IntegralContext`: `base`, `navigate`), never at the top level of a context.
- **One published package.** Framework adapters are subpath exports with optional peer deps (`astro`, `@nuxt/kit`, `@nuxt/schema`, `h3`, and `vue` / `react` / `react-dom` for the admin helpers).
- **SQLite only for now**, through libsql (a file or Turso). D1 and Postgres come later, behind the same `documents` shape.
- **Admin path is an adapter option** (`admin: '/cms'`, default `/admin`), not part of `integral.config.ts`: routes are registered at build time, before the config can load. `adminPath()` in `src/admin/html.ts` validates it; the page passes it to the admin router as `data-base`. `/api/cms` (`API_BASE`) stays fixed.
- **Relation ids live in the document JSON.** A string, or a string array for `many`. Reverse lookups (joins, delete checks) scan with `json_extract` / `json_each`. Id lists go in as one JSON parameter (`IN (SELECT value FROM json_each(?))`), so there is no variable limit. Populate runs one query per field per hop.
- **Validation and hooks live in the local API.** HTTP is a thin layer, so server code, HTTP and the admin behave the same.
- **Writes run in one transaction** with their hooks, `onDelete` effects and nested calls. Nested calls MUST go through the hook's `cms`.
- **Presets are data, not features.** No `findByPath`: paths are stored and filtered like any field. The SEO title fallback is computed by `seoMeta()` at render time and never stored.
- **Reads are public, writes need a session.** Pages render the content anyway, and the Nuxt composable needs an HTTP read path for client-side navigation. Drafts will have to gate here later.
- **Private is an HTTP rule.** The local API, hooks and the admin see every field. `http/index.ts` strips private fields from public responses.
- **Options the admin evaluates MUST be JSON.** Conditions, built-in checks and plain defaults run in both places; `validate`, function defaults and hooks run on the server only.

## Gotchas (each cost a debugging round)

- Nitro rewrites `typeof window` to `"undefined"` as plain text, even inside strings. Keep browser-only code out of server bundles.
- libsql loads `@libsql/<platform>` with a dynamic require:
  - If Vite bundles core, the native binding breaks. That's why the Astro adapter and `integralAdmin()` set core as `ssr.external` in builds. Dev does not bundle, so it stays internal there and Vite reloads it.
  - Nitro's tracer misses the binary. That's why the Nuxt module adds `traceInclude`.
- `tsdown --watch` MUST run with `--no-clean`. Otherwise Nitro rebuilds while `dist/` is empty and logs ENOENT errors. Never run `build:packages` while the watcher runs: the core build deletes `dist/` (including `dist/admin`) under the watcher.
- `Object.assign(el, { dataset: ... })` throws: `dataset` is a getter. Use `setAttribute`.
- Nitro v3 (TanStack Start) traces the libsql binary on its own. Nitro 2 (Nuxt) does not.
- TanStack Start streams HTML. Use `grep -a` on curl output, or grep treats it as binary and prints nothing.
- `nuxt preview` runs with cwd `.output/`, so a relative `file:./cms.db` lands in the build output and gets wiped. Use absolute paths; the Nuxt example uses `resolve('cms.db')`.
- Astro 7 `astro dev` / `astro preview` run as daemons. Use `npx astro dev stop`, `npx astro preview logs`.
- `astro preview` does not load `.env`. The script runs it through `node --env-file-if-exists=.env`.
- `astro check` does not detect `@astrojs/check` under Astro 7. Use `astro sync && tsc --noEmit`.
- Nuxt: use `nuxt typecheck`. Plain `vue-tsc --noEmit` with Nuxt's reference-only tsconfig checks nothing.
- `tsc --noEmit` in the Astro example never checks `.astro` frontmatter. To test `App.Locals` typing, use a `.ts` file.
- Nuxt's `.nuxt/types/nitro-routes.d.ts` imports every server handler for `$fetch` route types, and that file belongs to the app tsconfig project. Server runtime files in a module MUST import from `h3`, not `#imports`, or the app project cannot resolve them.
- tsdown `copy` with a directory `from` nests the directory under `to`. Use the parent as `to`.
- A stale Astro daemon or leftover `cms.db` makes sign-up return 403 (first-user-only). Run `astro dev stop` and delete the DB before a smoke test.
- `:memory:` libsql has one connection. Code inside a transaction MUST use `trx` (`q(core, s)` in `cms/scope.ts`), and hooks MUST call the `cms` they get, or the call blocks or fails with `TRANSACTION_ACTIVE`.
- `JSON.stringify` turns functions in arrays into `null`, so `/schema` strips `hooks` (a field named `hooks` stays, it has a `type`).
- A generic type parameter with a default (`C = {}`) gives context-sensitive functions in the argument that default as their contextual type, so their parameters are implicit `any`. `CmsOptions` intersects `collections` with a plain `Record<string, Collection>` inside `NoInfer` to give inline hooks a contextual type.
- Preset hooks type `data` as `any`. With `Record<string, any>`, a spread with a computed key (`{ ...data, [path]: x }`) is not assignable to a typed collection's `Data`. `collection` MUST stay optional in their argument type (`collection!` in the body); a required one is rejected by `CollectionHooks`.
- Query parsers (`parsePopulate()`, `parseSelect()`) build nested objects from raw query segments. They MUST use `Object.create(null)` nodes: on a plain `{}`, a `__proto__` segment returns `Object.prototype`, and the next write pollutes every object in the process.
- `tsc` colors its output in some shells, so `grep "error TS"` can match nothing and hide real errors. Use `tsc --noEmit --pretty false` when filtering.
- Generic inference skips excess property checks, so `populate` objects need `Exact` to reject unknown keys. For the same reason, type tests of field options use `satisfies Fields`, not `defineCollection()`.
- The recursive read types hit TS2589 on an untyped schema (`{ schema: Schema }`, the admin's client) without the `Wide` guard. `Http` / `HttpFields` in `client.ts` crash vue-tsc with a stack overflow there without their own `string extends keyof` guard.
- `ReadDoc` MUST stay `Simplify<Read<…, S> & SelectedMeta<S>>`, with `Wide` inside `Read`. `Wide<Cs> extends true ? … : Selected<Simplify<Resolve & Meta>, S>` hits TS2589 at `setup(defineCms(…))` in the tests (instantiation limit, with better-auth's types in the same statement), and `Selected<Simplify<Full & Meta>, S>` with `Wide` inside `Full` typechecks but makes tsdown's d.ts build run out of memory (`tsdown --watch` dies with it). Check both `pnpm typecheck` and `tsdown` after changing the read types.
- The client's `findOne` calls `client.find<K, O>(…)` with explicit type arguments; casting the result instead makes TS compare two deferred read types (TS2589). The Nuxt composable passes `options as never` on: TS cannot match its generic `Checked` to the client's, and its own parameter already checks the options.
- `keyof never` is every key, so `Exact<P, never>` would accept any object. `Exact` maps an object under a `true`-only key to `never`; that rejects an object on a relation `populate` does not resolve.
- An empty nested object is sent as the path itself over HTTP: `select: { parent: {} }` is `{ id }` locally but `true` (the whole value) over HTTP. Same for `populate`.
- A dangling relation id reads as `null` with the default populate. Tests that check stored ids MUST read with `populate: false`.
- Kysely 0.29 exports `Migrator` from `kysely/migration`, not from `kysely`.
- zsh: quote paths like `[slug].vue` in shell commands, or the glob silently matches nothing.
- tsdown d.ts output needs explicit types on the Nuxt module (`NuxtModule<Options>`). `@nuxt/schema` must be a peer, or its types get inlined.
- Nitro hook types (`nitro:config`) come from `import type {} from '@nuxt/nitro-server/augments'`.
- Hono `csrf()` only checks form-like content types. JSON requests are protected because browsers preflight them cross-origin and we send no CORS headers.
- TanStack Start throws `multiple entries detected` on a second client entry. `integralAdmin()` sets `isEntry = false` on the admin chunk in `generateBundle`, before Start's post hook reads it.
- `configureServer` also runs during `vite build` (TanStack/Nitro). Check `this.environment.config.command === 'serve'`, not whether a server exists.
- Dev servers bind `[::1]` and `curl localhost` hits them first. Test a production build on `HOST=127.0.0.1` and another port, with its own `DATABASE_URL`, or you test a leftover dev server and write into its DB.
- Browsers compile the HTML `pattern` attribute with the `v` flag, so the server does too. `<textarea>` ignores `pattern`.
- A leftover service worker on `localhost:3000` from another project can hijack navigation. If a page works in incognito but not normally, check DevTools → Application → Service workers.
- The admin's Tailwind scans only `packages/admin/src`. HTML that a host or plugin mount writes gets only the utilities the admin itself uses, plus `.input` / `.btn`. Use inline styles for the rest, or the class silently does nothing.
- `@ts-expect-error` covers the next line only. When oxfmt wraps a call over several lines, the directive MUST sit directly above the line with the invalid value, or `tsc` reports it unused plus the real error.
- A `defineCms({ ... } as never)` call infers `M = never`. A distributive or `[M] extends [MediaOptions]` conditional then hits TS2589; `MediaOf` checks `[M] extends [undefined]` and is applied to the return value, not inside `api()`.
- consola writes to `process.stderr`, not `console.error`. Tests that assert a log spy on `process.stderr.write`.
- shadcn-vue components import icons from `@lucide/vue` statically, which pulls every icon into the admin bundle and defeats `Icon.vue`'s lazy chunk. Generated components MUST use `Icon.vue` instead. The CLI also prepends a Google Fonts `@import` to `style.css`; remove it.
- IPX prefixes ids with `/` and treats a `getMeta()` of `undefined` as not found. The storage in `images/ipx.ts` strips the slash and returns `{}`.
- Without a session, a path that no public route matches answers 401 (the session middleware runs), not 404. Test "route missing" cases with a session.

## Smoke test

```sh
B=localhost:3000; J=/tmp/jar
curl -s -c $J -H 'content-type: application/json' -H "origin: http://$B" \
  -d '{"name":"Admin","email":"a@b.co","password":"password123"}' $B/api/cms/auth/sign-up/email
curl -s -b $J -H 'content-type: application/json' -H "origin: http://$B" \
  -d '{"title":"Hello","slug":"hello"}' $B/api/cms/collections/posts
curl -s $B/
```

Expect 200, 201, and the post in the page HTML. Delete the example's `cms.db` before and after.

Media, on the standalone example (`B=127.0.0.1:3200` or a production build on another port): upload a PNG in one part, then fetch the original and a variant.

```sh
S=$(stat -f%z hero.png)  # Linux: stat -c%s
ID=$(curl -s -b $J -H 'content-type: application/json' -H "origin: http://$B" \
  -d "{\"filename\":\"hero.png\",\"mimeType\":\"image/png\",\"size\":$S}" $B/api/cms/media/uploads | node -pe 'JSON.parse(require("fs").readFileSync(0)).id')
curl -s -b $J -X PUT -H "origin: http://$B" --data-binary @hero.png $B/api/cms/media/uploads/$ID/parts/1
curl -s -b $J -H 'content-type: application/json' -H "origin: http://$B" -d '{"parts":[]}' $B/api/cms/media/uploads/$ID/complete
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' $B/api/cms/media/files/hero.png
curl -s -o /dev/null -w '%{http_code} %{content_type}\n' "$B/api/cms/media/img/f_webp&q_80/hero.png"
```

Expect 201, `{"etag":"1"}`, the media document with `width` / `height`, `200 image/png` and `200 image/webp`. Delete `.uploads/` with `cms.db`.

## Conventions

- TypeScript strict. Keep the file count small and add no abstraction until a second use exists.
- The local API validates every write with `parseData()`. Every write route MUST stay behind the session middleware. Read routes are public and MUST only accept field names that exist in the schema and that the caller can see (`private`).
- `src/schema/condition.ts` MUST stay free of imports; the admin bundles it.
- Admin UI: plain Vue SFCs with `<script setup>`, Tailwind classes, and the shared `.input` / `.btn` / `.btn-ghost` classes in `style.css`. Host inputs render in the admin's light DOM, so they can use those classes too.
- Versions in use: Astro 7, Nuxt 4.5 (nitropack 2, h3 v1), TanStack Start 1.168 (nitro 3 beta, React 19), Vite 8, TypeScript 6, better-auth 1.7, kysely 0.29, Hono 4, zod 4.
- never mention claude in commits
