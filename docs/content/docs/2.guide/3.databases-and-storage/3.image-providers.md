title: Image Providers
description: Resize images on the server or through an image service.
---

An image provider makes resized copies of each image, called variants, and fills `srcset`. You set it in `media.images`:

```ts [tenon.config.ts]
import { defineCms } from "tenoncms";
import { ipx } from "tenoncms/media/ipx";
import { local } from "tenoncms/media/local";

export default defineCms({
  // ...
  media: {
    storage: local({ dir: ".uploads" }),
    images: { provider: ipx() },
  },
});
```

Each provider is its own import, `tenoncms/media/<name>`, so a site loads only the one it uses. `npm create tenoncms` asks for one and writes its config.

## Do you need one?

Without a provider, images are served as uploaded. A read returns the original as `src` and an empty `srcset`. That is enough when:

- the images are small, or
- your framework resizes them, like Astro's `<Image>` or Nuxt Image. See [Use your framework's image component](/docs/core/content-modeling/fields/image#use-your-frameworks-image-component).

The admin still shows small previews. On upload, the browser draws each image at 320 px on the short side and stores the copy. This needs no package and no work on the server.

Use a provider when you want responsive images without another tool, for example because editors upload large photos.

| Your site runs on                                     | Use                                                |
| ----------------------------------------------------- | -------------------------------------------------- |
| A Node server                                         | `ipx()`                                            |
| Cloudflare Workers                                    | `cloudflare({ binding: env.IMAGES })`              |
| Vercel                                                | `vercel()`                                         |
| Netlify                                               | `netlify()`                                        |
| Any host behind Cloudflare with image transformations | `cloudflare()`                                     |
| Any host, with an image service you already use       | `imgix()`, `cloudinary()`, `imagekit()`, `bunny()` |
| Any host, with your own image server                  | `imgproxy()`, `thumbor()`                          |

## Providers

There are two kinds of provider:

- A **rendering** provider makes the variants itself. Tenon serves them at `/_tenon/media/img/<modifiers>/<key>` and stores them in your media storage, under `.variants/<key>/`. It renders a variant on its first request, or right after the upload with `prerender: true`. It serves only the variants your config can produce, so nobody can ask for other sizes.
- A **URL** provider builds URLs for an image service. Tenon renders and stores nothing. The service MUST be able to load the original.

| Provider       | Import                      | Kind                               | Runs on                                                    | Ignores                                         |
| -------------- | --------------------------- | ---------------------------------- | ---------------------------------------------------------- | ----------------------------------------------- |
| `ipx()`        | `tenoncms/media/ipx`        | Rendering, with sharp              | Node, Bun, Vercel functions                                | Nothing                                         |
| `cloudflare()` | `tenoncms/media/cloudflare` | Rendering with `binding`, else URL | Workers with `binding`, else any site on a Cloudflare zone | Nothing                                         |
| `vercel()`     | `tenoncms/media/vercel`     | URL                                | Vercel                                                     | `height`, `fit`, `format`, `background`, `blur` |
| `netlify()`    | `tenoncms/media/netlify`    | URL                                | Netlify and `netlify dev`                                  | `background`, `blur`                            |
| `imgix()`      | `tenoncms/media/imgix`      | URL                                | Anywhere                                                   | Nothing                                         |
| `cloudinary()` | `tenoncms/media/cloudinary` | URL                                | Anywhere                                                   | Nothing                                         |
| `imagekit()`   | `tenoncms/media/imagekit`   | URL                                | Anywhere                                                   | Nothing                                         |
| `bunny()`      | `tenoncms/media/bunny`      | URL                                | Anywhere                                                   | `fit`, `format`, `background`                   |
| `imgproxy()`   | `tenoncms/media/imgproxy`   | URL, self-hosted                   | Anywhere                                                   | Nothing                                         |
| `thumbor()`    | `tenoncms/media/thumbor`    | URL, self-hosted                   | Anywhere                                                   | Nothing                                         |

"Ignores" lists the [image options](#sizes-and-presets) a provider cannot apply.

::tabs

:::tabs-item{label="ipx"}

`ipx()` renders variants with [IPX](https://github.com/unjs/ipx), which uses sharp. Tenon does not install it, because sharp is a large native package:

::::code-group{sync="pm"}

```bash [npm]
npm install ipx@4.0.0-beta.1
```

```bash [pnpm]
pnpm add ipx@4.0.0-beta.1
```

```bash [yarn]
yarn add ipx@4.0.0-beta.1
```

```bash [bun]
bun add ipx@4.0.0-beta.1
```

::::

```ts [tenon.config.ts]
import { ipx } from "tenoncms/media/ipx";

images: { provider: ipx({ prerender: true }) },
```

::::field-group

:::::field{name="prerender" type="boolean"}
Renders every variant right after the upload, instead of on its first request. Default: `false`.
:::::

::::

- sharp is native code. Install the packages on a machine with the same OS and CPU as the server, or in the same container image.
- `tenoncms/media/ipx` throws on Cloudflare Workers.

:::

:::tabs-item{label="Cloudflare"}

`cloudflare()` has two modes.

**With an Images binding**, on Workers, Tenon renders the variants through Cloudflare Images and stores them. `wrangler dev` renders locally:

::::code-group

```ts [tenon.config.ts]
import { env } from "cloudflare:workers";
import { cloudflare } from "tenoncms/media/cloudflare";

images: { provider: cloudflare({ binding: env.IMAGES }) },
```

```jsonc [wrangler.jsonc]
{
  "images": { "binding": "IMAGES" },
}
```

::::

**Without a binding**, variant URLs point to `/cdn-cgi/image/…` on the zone that serves the site. Tenon renders nothing. The site MUST be proxied by Cloudflare, with image transformations on for the zone. This also works for a site on Node or Vercel.

```ts [tenon.config.ts]
images: { provider: cloudflare() },
```

::::field-group

:::::field{name="binding" type="ImagesBinding"}
The Images binding, like `env.IMAGES` with `env` from `cloudflare:workers`. Default: URLs on `/cdn-cgi/image/`.
:::::

:::::field{name="prerender" type="boolean"}
Renders every variant right after the upload. Needs `binding`. Default: `false`.
:::::

::::

:::

:::tabs-item{label="Vercel"}

`vercel()` uses Vercel Image Optimization. Outside Vercel, as in development, it returns the originals, so development needs no setup:

```ts [tenon.config.ts]
import { vercel } from "tenoncms/media/vercel";

images: { provider: vercel() },
```

On Vercel, Image Optimization MUST be on, with the same widths as `images.sizes`. Set them in the framework config:

::::code-group{sync="framework"}

```ts [Astro]
// astro.config.ts
import vercel from "@astrojs/vercel";

export default defineConfig({
  adapter: vercel({ imagesConfig: { sizes: [320, 640, 1024, 1536, 1920], domains: [] } }),
});
```

```ts [Nuxt]
// nuxt.config.ts
export default defineNuxtConfig({
  nitro: { vercel: { config: { images: { sizes: [320, 640, 1024, 1536, 1920], domains: [] } } } },
});
```

```ts [TanStack Start]
// vite.config.ts. Standalone uses the same `nitro()` option.
const vercel = { config: { images: { sizes: [320, 640, 1024, 1536, 1920], domains: [] } } };

export default defineConfig({
  plugins: [tanstackStart(), nitro({ vercel }), viteReact(), tenonAdmin()],
});
```

::::

- A width between two allowed widths rounds up to the next one.
- Vercel picks the format from the browser. Only `width` and `quality` apply.
- Files in a bucket: set `publicUrl` on the storage, and allow its host in `remotePatterns` of the same `images` block.
- The Vercel starters of `npm create tenoncms` write this config with the default widths. Change both lists together.

::::field-group

:::::field{name="sizes" type="number[]"}
The widths Vercel allows. They MUST equal the `sizes` of the Vercel image config. Default: `[320, 640, 1024, 1536, 1920]`.
:::::

::::

:::

:::tabs-item{label="Netlify"}

`netlify()` uses the Netlify Image CDN. It works on Netlify and in `netlify dev`:

```ts [tenon.config.ts]
import { netlify } from "tenoncms/media/netlify";

images: { provider: netlify() },
```

A file on another origin, like a public bucket, MUST be listed in `remote_images` of `netlify.toml`.

::::field-group

:::::field{name="baseURL" type="string"}
Where the Image CDN answers. Default: `/.netlify/images`.
:::::

:::tabs-item{label="imgix"}

```ts [tenon.config.ts]
import { imgix } from "tenoncms/media/imgix";

images: { provider: imgix({ baseURL: process.env.IMGIX_BASE_URL! }) },
```

URLs are `<baseURL>/<key>?w=…`. Point the imgix source at the bucket, or at `https://<site>/_tenon/media/files/` for files on the local disk.

::::field-group

:::::field{name="baseURL" type="string" required}
The imgix domain, like `https://my-site.imgix.net`.
:::::

::::

:::

:::tabs-item{label="Cloudinary"}

```ts [tenon.config.ts]
import { cloudinary } from "tenoncms/media/cloudinary";

images: { provider: cloudinary({ baseURL: process.env.CLOUDINARY_BASE_URL! }) },
```

`baseURL` decides where Cloudinary finds the file:

| `baseURL`                                                  | Cloudinary loads                                                                                               |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `https://res.cloudinary.com/<cloud>/image/upload/<folder>` | The file through an auto-upload mapping of `<folder>` to the bucket or to `https://<site>/_tenon/media/files/` |
| `https://res.cloudinary.com/<cloud>/image/upload`          | A file you uploaded to Cloudinary yourself. The key without its extension is the public ID                     |
| `https://res.cloudinary.com/<cloud>/image/fetch`           | The file URL. Set `origin`, so URLs of local files are absolute                                                |

::::field-group

:::::field{name="baseURL" type="string" required}
The delivery URL. See the table.
:::::

:::::field{name="origin" type="string"}
Makes relative file URLs absolute for `…/image/fetch`, like `https://example.com`.
:::::

::::

:::

:::tabs-item{label="ImageKit"}

```ts [tenon.config.ts]
import { imagekit } from "tenoncms/media/imagekit";

images: { provider: imagekit({ baseURL: process.env.IMAGEKIT_BASE_URL! }) },
```

URLs are `<baseURL>/<key>?tr=…`. Point the ImageKit origin at the bucket, or at `https://<site>/_tenon/media/files/`.

::::field-group

:::::field{name="baseURL" type="string" required}
The URL endpoint, like `https://ik.imagekit.io/<id>`.
:::::

::::

:::

:::tabs-item{label="Bunny"}

```ts [tenon.config.ts]
import { bunny } from "tenoncms/media/bunny";

images: { provider: bunny({ baseURL: process.env.BUNNY_BASE_URL! }) },
```

URLs are `<baseURL>/<key>?width=…`. Point the pull zone at the bucket, or at `https://<site>/_tenon/media/files/`. Bunny picks the format.

::::field-group

:::::field{name="baseURL" type="string" required}
A pull zone with Bunny Optimizer on, like `https://my-site.b-cdn.net`.
:::::

::::

:::

:::tabs-item{label="imgproxy"}

```ts [tenon.config.ts]
import { imgproxy } from "tenoncms/media/imgproxy";

images: {
  provider: imgproxy({
    baseURL: process.env.IMGPROXY_URL!,
    key: process.env.IMGPROXY_KEY,
    salt: process.env.IMGPROXY_SALT,
  }),
},
```

imgproxy loads the file URL. URLs of local files are relative, so set `IMGPROXY_BASE_URL` on the imgproxy server to your site, or pass `origin`.

::::field-group

:::::field{name="baseURL" type="string" required}
The imgproxy server, like `https://img.example.com`.
:::::

:::::field{name="key" type="string"}
The signing key, in hex. With `key` and `salt`, URLs are signed. Without them, URLs are `unsafe`, which the server MUST allow.
:::::

:::::field{name="salt" type="string"}
The signing salt, in hex.
:::::

:::::field{name="origin" type="string"}
Makes relative file URLs absolute, like `https://example.com`. Not needed with `IMGPROXY_BASE_URL`.
:::::

::::

:::

:::tabs-item{label="Thumbor"}

```ts [tenon.config.ts]
import { thumbor } from "tenoncms/media/thumbor";

images: {
  provider: thumbor({
    baseURL: process.env.THUMBOR_URL!,
    key: process.env.THUMBOR_KEY,
    origin: "https://example.com",
  }),
},
```

Thumbor loads the file URL through its HTTP loader.

::::field-group

:::::field{name="baseURL" type="string" required}
The Thumbor server, like `https://thumbor.example.com`.
:::::

:::::field{name="key" type="string"}
The security key. With it, URLs are signed. Without it, URLs are `unsafe`, which the server MUST allow.
:::::

:::::field{name="origin" type="string"}
Makes relative file URLs absolute, like `https://example.com`.
:::::

::::

:::

With a [`prefix`](/docs/guide/databases-and-storage/media-storage#share-a-bucket) on the storage, a URL provider still builds `<baseURL>/<key>`. Point the service at the prefix folder of the bucket.

## Sizes and presets

`media.images` sets how Tenon builds `src` and `srcset` for every image:

```ts [tenon.config.ts]
import { defineCms } from "tenoncms";
import { ipx } from "tenoncms/media/ipx";
import { local } from "tenoncms/media/local";

export default defineCms({
  // ...
  media: {
    storage: local({ dir: ".uploads" }),
    images: {
      provider: ipx(),
      sizes: [320, 640, 1024, 1536, 1920],
      format: "webp",
      quality: 85,
      presets: {
        avatar: { width: 128, height: 128, fit: "cover" },
      },
    },
  },
});
```

- `sizes` are the widths in `srcset`. Widths above the original are left out. Default: `[320, 640, 1024, 1536, 1920]`.
- `format` and `quality` apply to every variant. Default: `"webp"` and `85`.
- `presets` are named sets of options: `width`, `height`, `fit`, `format`, `quality`, `background` and `blur`. A field uses one with `image: { preset: "avatar" }`. A field that names a missing preset stops the server at startup.
- `maxSize` is the largest image that gets variants. Default: 50 MB.

SVG files and images above `maxSize` get the original as `src` and an empty `srcset`.

A field can override these options. See [Image sizes](/docs/core/content-modeling/fields/image#image-sizes). Every option is in the [configuration reference](/docs/core/reference/configuration#media).

### After a change

Stored variants do not follow a change to `sizes`, `presets`, `format`, `quality` or the provider. Run [`tenon media regenerate`](/docs/cli/media):

```bash
npx tenon media regenerate
```

- It deletes the stored variants that your options no longer produce.
- With `prerender`, it renders the missing ones. `--force` renders all of them again, for example after a sharp upgrade.
- A config that runs only on Cloudflare cannot run in the CLI. Call `cms.media.regenerate()` there, from a route or a job.
- A URL provider stores nothing. Its new URLs take effect on the next read.

## Write your own provider

A provider is an object with `getImage()`. This one builds URLs for an image service:

```ts [cms/my-images.ts]
import type { ImageProvider } from "tenoncms";

export const myImages = (baseURL: string): ImageProvider => ({
  getImage({ key, width }, modifiers) {
    const params = new URLSearchParams({ w: String(modifiers.width ?? width) });
    if (modifiers.quality) params.set("q", String(modifiers.quality));
    return { url: `${baseURL}/${encodeURI(key)}?${params}` };
  },
});
```

::field-group

:::field{name="getImage" type="(src, modifiers) => { url }" required}
Builds the URL of one variant. `src` holds the storage `key`, the `url` of the original, `width` and `height`. It runs on the server, on every read.
:::

:::field{name="render" type="(key, modifiers, storage) => Promise<{ data, mimeType }>"}
Renders a variant from the original in `storage`. With it, Tenon serves and stores the variants, like `ipx()`.
:::

:::field{name="prerender" type="boolean"}
Renders every variant right after the upload. Needs `render`.
:::

::

The URL providers port the mappings of [Nuxt Image](https://image.nuxt.com/providers). Another Nuxt Image provider translates the same way.
