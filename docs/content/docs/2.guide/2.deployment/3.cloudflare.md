## How it runs

- The CMS lives in one Durable Object with its own database. Astro only, for now.
- UI: `note` callout.

## Set it up

- `durableObject()` in the config, `tenonObject(cms)` in the Worker entry, the `CMS` binding in `wrangler.jsonc`.
- UI: `steps`; `code-group` for the three files.

## Read content

- `Astro.locals.tenon` is the client over the object, not the local API. The differences in a table.
- Pages that read the CMS render per request.

## Media and secrets

- R2 through a binding, Cloudflare Images for variants.
- `.dev.vars` in development, Wrangler secrets in production.

## Deploy

- `wrangler deploy` and the bindings it creates.
- The CLI talks to the deployed site with `--url`.
