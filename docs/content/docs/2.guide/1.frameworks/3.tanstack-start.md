TanStack Start needs no module. `tenonAdmin()` in the Vite config builds the admin, and four route files hand requests to the CMS. Server functions read content.

## Create a project

Run the wizard and pick **TanStack Start**:

::code-group{sync="pm"}

```bash [npm]
npm create tenoncms@latest
```

```bash [pnpm]
pnpm create tenoncms
```

```bash [yarn]
yarn create tenoncms
```

```bash [bun]
bun create tenoncms
```

::

The starter has `vite.config.ts` with `tenonAdmin()`, `tenon.config.ts`, a `posts` collection, the API and admin routes, and two pages. Start it with `npm run dev`, open the URL it prints and add `/admin`. See [create-tenoncms](/docs/cli/create-tenoncms) for every question and flag.

## Add to an existing project

This setup uses a SQLite file. For the other databases, see [Databases](/docs/guide/databases-and-storage/databases).

::steps{level="3"}

### Install the packages

Tenon needs a server build, so add Nitro too:

:::code-group{sync="pm"}

```bash [npm]
npm install tenoncms @libsql/client
npm install -D nitro
```

```bash [pnpm]
pnpm add tenoncms @libsql/client
pnpm add -D nitro
```

```bash [yarn]
yarn add tenoncms @libsql/client
yarn add -D nitro
```

```bash [bun]
bun add tenoncms @libsql/client
bun add -D nitro
```

:::

### Add the Vite plugin

`tenonAdmin()` builds the admin and runs the job clock:

```ts [vite.config.ts]
import { tanstackStart } from "@tanstack/react-start/plugin/vite";
import viteReact from "@vitejs/plugin-react";
import { nitro } from "nitro/vite";
import { tenonAdmin } from "tenoncms/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [tanstackStart(), nitro(), viteReact(), tenonAdmin()],
});
```

### Add the server routes

The API route hands every request method to the CMS. The admin route serves the admin page. The sitemap and `robots.txt` routes are optional:

:::code-tree{defaultValue="src/routes/[_]tenon.$.ts"}

```ts [src/routes/[_]tenon.$.ts]
import { createFileRoute } from "@tanstack/react-router";
import cms from "../../tenon.config";

const handle = ({ request }: { request: Request }) => cms.fetch(request);

export const Route = createFileRoute("/_tenon/$")({
  server: { handlers: { ANY: handle } },
});
```

```ts [src/routes/admin.$.ts]
import { createFileRoute } from "@tanstack/react-router";
import html from "#tenon/admin-html";

export const Route = createFileRoute("/admin/$")({
  server: {
    handlers: {
      GET: () => new Response(html, { headers: { "content-type": "text/html; charset=utf-8" } }),
    },
  },
});
```

```ts [src/routes/sitemap[.]xml.ts]
import { createFileRoute } from "@tanstack/react-router";
import cms from "../../tenon.config";

export const Route = createFileRoute("/sitemap.xml")({
  server: { handlers: { GET: ({ request }) => cms.fetch(request) } },
});
```

```ts [src/routes/robots[.]txt.ts]
import { createFileRoute } from "@tanstack/react-router";
import cms from "../../tenon.config";

export const Route = createFileRoute("/robots.txt")({
  server: { handlers: { GET: ({ request }) => cms.fetch(request) } },
});
```

:::

The brackets escape characters that TanStack Router reads as syntax. A file named `_tenon.$.ts` is a pathless layout route and never matches `/_tenon`.

### Register the types

Add `tenoncms/register` to `types`, and point `#tenon/config` at your config:

```json [tsconfig.json]
{
  "compilerOptions": {
    "types": ["vite/client", "node", "tenoncms/register"],
    "paths": { "#tenon/config": ["./tenon.config.ts"] }
  }
}
```

This types `#tenon/admin-html`, and `createClient()` from `tenoncms/client` without a type argument.

### Create the CMS instance

Create `tenon.config.ts` at the project root:

```ts [tenon.config.ts]
import { defineCms } from "tenoncms";
import { libsql } from "tenoncms/libsql";
import { posts } from "./cms/collections/posts";

export default defineCms({
  collections: { posts },
  database: libsql(process.env.DATABASE_URL ?? "file:./cms.db"),
  secret: process.env.TENON_SECRET!,
  site: { url: process.env.TENON_SITE_URL, name: "My Site" },
});
```

For the `posts` collection, see [Add a collection](/docs/core/getting-started/existing-site#add-a-collection).

### Set the secret

Generate a secret with `openssl rand -hex 32` and put it in `.env`:

```bash [.env]
TENON_SECRET=<your secret>
```

Keep `.env`, `cms.db*` and `.uploads` out of git.

### Create the admin account

Run `npm run dev`, open the URL it prints and add `/admin`. The first account you create is the admin.

::

## Read content

Loaders run on the server and in the browser, but the CMS runs only on the server. Read content in a server function, and call it from the loader:

```tsx [src/routes/posts/$slug.tsx]
import { createFileRoute, notFound } from "@tanstack/react-router";
import { createServerFn } from "@tanstack/react-start";
import { getRequest } from "@tanstack/react-start/server";
import cms from "../../../tenon.config";

const getPost = createServerFn()
  .validator((slug: string) => slug)
  .handler(async ({ data: slug }) => {
    const tenon = await cms.withSession(getRequest());
    const post = await tenon.findOne("posts", { where: { slug } });
    if (!post) throw notFound();
    return post;
  });

export const Route = createFileRoute("/posts/$slug")({
  loader: ({ params }) => getPost({ data: params.slug }),
  component: Post,
});

function Post() {
  const post = Route.useLoaderData();
  return <h1>{post.title}</h1>;
}
```

`cms.withSession(getRequest())` reads as the user of the request. An editor in the preview reads drafts, and the [access rules](/docs/core/users-and-access/access-control) apply. The imported `cms` skips both, so use it only for content every visitor may see. See [Drafts](/docs/core/working-with-content/reading#drafts).

## Render and preview

The components of `tenoncms/react` render fields as HTML: `Image`, `Picture`, `Link`, `Blocks`, `Richtext` and `Seo`. They use no hooks, so they also work as server components. See [Components](/docs/core/building-your-site/components).

The live preview needs two additions:

1. Call `preview()` once in the root route. For visitors without a session, it does nothing.

   ```tsx [src/routes/__root.tsx]
   import { useEffect } from "react";
   import { preview } from "tenoncms/preview";

   function Root() {
     useEffect(() => preview(), []);
     // ...
   }
   ```

2. Pass the loader data through `useDraft()`. It merges unsaved changes, so the whole page follows while the editor types:

   ```tsx [src/routes/posts/$slug.tsx]
   import { edit } from "tenoncms/preview";
   import { useDraft } from "tenoncms/preview/react";

   function Post() {
     const post = useDraft("posts", Route.useLoaderData());
     return <h1 data-cms={edit("posts", post.id, "title")}>{post.title}</h1>;
   }
   ```

`edit()` marks what a field renders. See [Live preview](/docs/core/building-your-site/live-preview).

TanStack Start has no adapter for languages. Read the language from the URL with `localeFromPath()` in a server function. See [Localization](/docs/core/working-with-content/localization#per-framework).

## `tenonAdmin()` options

::field-group
:::field{name="entry" type="string"}
The file that exports the CMS instance, relative to the project root. Default: `"./tenon.config.ts"`.
:::

:::field{name="jobs" type="boolean"}
Runs due jobs every minute through the Nitro task `tenon:jobs`. Default: `true`. On Vercel, Nitro turns the task into a Vercel Cron Job. See [The clock](/docs/core/operations/jobs/clock).
:::
::

- `tenonAdmin()` throws when `tenon.config.ts` sets `admin: false`. Remove the plugin and the admin route then.
- It reads `admin.path` at startup. For another path, like `/cms`, rename the admin route to `src/routes/cms.$.ts` and pass the path to `preview({ admin: "/cms" })`. See [Admin path](/docs/core/customization/admin#admin-path).
- It keeps `tenoncms` out of the server bundle, because bundling it breaks the native driver of libSQL.

::warning
Vercel Hobby allows one cron job a day, and a deploy with a cron every minute fails. The Vercel starter sets `tenonAdmin({ jobs: false })`. Call [the clock route](/docs/core/operations/jobs/clock#the-clock-route) from a cron service instead, or remove `jobs: false` on the Pro plan.
::
