A plugin keeps one feature in one place: its collections, hooks, routes and admin pieces. This recipe writes a small plugin in your project, then shows what else a plugin can define and how to publish one on npm.

## Before you start

- Read [Plugins](/docs/core/customization/plugins) for how a site uses a plugin.
- The [example plugin](/docs/core/customization/plugins#the-example-plugin) uses every option once. Its source is a good model to copy.

## A first plugin

This plugin adds an `announcements` collection and a public route that returns the active announcement.

::steps{level="3"}

### Define the plugin

A plugin is a function that returns `definePlugin()`. The function takes the plugin's options:

```ts [cms/plugins/announcements.ts]
import { defineCollection, definePlugin } from "tenoncms";

export function AnnouncementsPlugin() {
  return definePlugin({
    name: "announcements",
    collections: {
      announcements: defineCollection({
        titleField: "text",
        fields: {
          text: { type: "text", required: true },
          active: { type: "boolean" },
        },
      }),
    },
    publicRoutes: (api) =>
      api.get("/current", async (c) => {
        const current = await c.var.cms.findOne("announcements", { where: { active: true } });
        return current ? c.json(current) : c.notFound();
      }),
  });
}
```

- `name` is lowercase letters, digits and `-`. It prefixes the routes: this one answers at `/_tenon/announcements/current`.
- `publicRoutes` run without a session, so `c.var.cms` has no user, and the access rules deny writes.

### Add it to the config

```ts [tenon.config.ts]
import { defineCms } from "tenoncms";
import { AnnouncementsPlugin } from "./cms/plugins/announcements";

export default defineCms({
  // ...
  plugins: [AnnouncementsPlugin()],
});
```

Start the dev server. The admin lists **Announcements** in the sidebar.

### Read it

The collection is typed like your own, so server code reads it directly:

```ts
const current = await cms.findOne("announcements", { where: { active: true } });
```

A site on another origin calls the route:

```ts
const current = await client.request("/announcements/current");
```

### Install a default

A plugin's `seed` runs the first time the plugin starts on a database, also on one that has content. Use it to install defaults:

```ts [cms/plugins/announcements.ts]
return definePlugin({
  name: "announcements",
  // ...
  seed: async ({ cms }) => {
    await cms.create("announcements", { text: "Welcome to the new site", active: false });
  },
});
```

A plugin that is removed and added again does not seed again.

::

To add an input, a page or an admin bar item, import browser code from a `.client.ts` module, as in your own config. See [Custom fields](/docs/core/customization/custom-fields) and [Build a custom field](/docs/guide/recipes/build-a-custom-field).

## What a plugin can define

A plugin's additions merge before yours, in the order of `plugins`. See [Plugins](/docs/core/customization/plugins#what-a-plugin-can-define) for a more information.

## Publish it

A plugin on npm is an ordinary package with two halves: the server half from `definePlugin()`, and the browser half behind its `clientRef()` calls.

::code-tree{defaultValue="package.json"}

```json [package.json]
{
  "name": "cms-plugin-quotes",
  "type": "module",
  "exports": {
    ".": { "types": "./dist/index.d.mts", "default": "./dist/index.mjs" },
    "./admin": { "types": "./dist/admin/index.d.mts", "default": "./dist/admin/index.mjs" },
    "./admin/bar": { "types": "./dist/admin/bar.d.mts", "default": "./dist/admin/bar.mjs" }
  },
  "files": ["dist"],
  "peerDependencies": { "tenoncms": "^0.28.0" }
}
```

```ts [src/index.ts]
import { clientRef } from "tenoncms/admin";
import { definePlugin } from "tenoncms";

export function QuotesPlugin() {
  return definePlugin({
    name: "quotes",
    admin: {
      pages: {
        stats: { mount: clientRef("cms-plugin-quotes/admin#mountStats") },
      },
      adminBar: {
        items: {
          count: { label: "Quotes", mount: clientRef("cms-plugin-quotes/admin/bar#mountCount") },
        },
      },
    },
  });
}
```

```ts [src/admin/index.ts]
import type { Mount, PageContext } from "tenoncms/admin";

export const mountStats: Mount<PageContext> = (el) => {
  el.textContent = "Quote statistics";
  return () => el.replaceChildren();
};
```

```ts [src/admin/bar.ts]
import type { AdminBarItemContext, Mount } from "tenoncms/admin";

export const mountCount: Mount<AdminBarItemContext> = (el) => {
  el.textContent = "Quotes";
  el.style.fontWeight = "600";
  return () => el.replaceChildren();
};
```

```ts [tsdown.config.ts]
import { defineConfig } from "tsdown";
import Vue from "unplugin-vue/rolldown";

// Bundled into the admin chunks, so the host installs neither Vue nor React.
const bundled = /^(vue|react|react-dom|scheduler)(\/|$)|^@vue\/|^tenoncms\/admin\/(vue|react)$/;

export default defineConfig({
  plugins: [Vue({ isProduction: true })],
  entry: ["src/index.ts", "src/admin/index.ts", "src/admin/bar.ts"],
  platform: "neutral",
  fixedExtension: true,
  // Everything else, like `tenoncms` and `hono`, comes from the host.
  external: (id, importer) => !!importer && !id.startsWith(".") && !bundled.test(id),
  // One CSS file per chunk, so only styled entries load CSS.
  css: { inject: true, splitting: true },
  define: {
    "process.env.NODE_ENV": '"production"',
    __VUE_OPTIONS_API__: "true",
    __VUE_PROD_DEVTOOLS__: "false",
  },
  dts: { vue: true },
});
```

::

The build uses `tsdown`, `@tsdown/css`, and `unplugin-vue` for Vue components. Every published plugin MUST get these right:

- **`tenoncms` is a peer dependency and stays external.** A bundled copy gives the host two copies of core, which breaks `clientRef()` and the types. `tenoncms/admin` is the only core import the browser half needs.
- **Ship the browser half compiled.** The host's build does not compile `.vue`, JSX or TypeScript from `node_modules`. Bundle Vue or React into the admin chunks, as above, or write plain DOM. The host then installs no extra package.
- **`clientRef()` takes a package path, as a literal string.** `clientRef("cms-plugin-quotes/admin#mountStats")` resolves from the host's project root, so the host installs the plugin there. The adapters find the call by reading the module graph of `tenon.config.ts`, so the config MUST import the plugin statically.
- **Give the admin bar its own entry.** The bar loads on every page of the site. Everything it reaches MUST be free of CSS and of Vue `<style>` blocks, and the bar's shadow root gets no page CSS. Keep the bar mounts in a file like `admin/bar` and style them inline. The adapters reject a plugin that breaks this at startup.
- **Scope the plugin's CSS.** The admin's Tailwind does not scan plugin code, and plugin CSS applies to the whole admin. Scope every selector: a page class, scoped styles or a Tailwind `prefix()`. See [Styles and UI libraries](/docs/core/customization/styles-and-ui-libraries).
- **Build the types.** `definePlugin()` keeps the collection and global names, so the host gets `cms.find("quotes")` typed.

Before you publish, run `npm pack`, install the tarball in a test site and start its dev server once. A wrong `exports` entry, a bundled copy of `tenoncms` or CSS in the bar's graph shows up there.

### Import browser code instead of `clientRef()`

A plugin in your project imports `.client.ts` modules like your config does. A published plugin builds its server and browser halves apart, so its server build needs `clientModules()` from `tenoncms/vite`. It turns the imports into `clientRef()` calls with the package path:

```ts [tsdown.config.ts]
import { clientModules } from "tenoncms/vite";

const serverPlugin = clientModules({
  root: import.meta.dirname,
  server: true,
  references: { "./src/stats.client.ts": "cms-plugin-quotes/admin" },
});
```

- Add `serverPlugin` to the `plugins` of the server build only. Never use `server: true` in the browser build.
- Map every browser module that the server build reaches. A module without an entry would point into the host's project.
- Build `src/stats.client.ts` as the browser entry behind the `./admin` export, and ship the types of both halves.

Plain `clientRef()` calls need no extra build step.
