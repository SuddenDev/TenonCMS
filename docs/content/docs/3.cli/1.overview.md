Tenon has two command-line tools. `create-tenoncms` starts a new project. `tenon` maintains a project: it backs it up, restores it, upgrades it and manages its users. Both need Node 24 or newer.

## Two commands

| Command                                            | What it does                               |
| -------------------------------------------------- | ------------------------------------------ |
| [`npm create tenoncms`](/docs/cli/create-tenoncms) | Creates a new project from a starter       |
| [`tenon backup`](/docs/cli/backup)                 | Writes all data into a ZIP file            |
| [`tenon restore`](/docs/cli/backup#tenon-restore)  | Replaces all data with a backup            |
| [`tenon users`](/docs/cli/users)                   | Invites, recovers and manages users        |
| [`tenon media regenerate`](/docs/cli/media)        | Renders image variants again               |
| [`tenon upgrade`](/docs/cli/upgrade)               | Installs the latest `tenoncms`             |
| `tenon login`, `tenon logout`                      | Signs in to a deployed site, and out again |

`tenon` comes with the `tenoncms` package, so every project that has `tenoncms` has it. Run it with your package manager:

```sh
npx tenon backup
```

`npx tenoncms backup` is the same command. `npx tenon --help` lists every command and flag.

::note
Older projects MAY still have the `@tenoncms/cli` package. Remove it: `tenoncms` has the command now.
::

## Local or remote

Each command works on the project in the current folder, or on a running site.

### On the local project

Without `--url`, the CLI loads `tenon.config.ts` and opens the database itself, like your dev server does. It needs no sign-in.

- It reads `.env` first.
- In Astro, the defaults of `env.schema` in `astro.config.ts` apply.
- In Nuxt, it loads `runtimeConfig` from `nuxt.config.ts`, with the `NUXT_` variables over it.
- `--config <file>` loads another config file.

This works for SQLite, Turso, Postgres and PGlite. A config for Cloudflare runs only on Cloudflare, so use `--url` there.

### On a running site

With `--url`, the CLI talks to a running site over HTTP, local or deployed. Sign in first:

```sh
npx tenon login https://example.com
npx tenon backup --url https://example.com
```

`tenon login` shows a code and opens the admin in your browser. A signed-in user approves the code there.

- Without a URL, `tenon login` asks for it.
- `--no-open` prints the link instead of opening the browser.
- The session lasts like a normal session: 7 days, renewed on use. It is stored per site in `~/.config/tenon/credentials.json`.
- `tenon logout https://example.com` ends it.
- A site with `admin: false` has no sign-in page for the CLI. Use an [API key](/docs/core/users-and-access/api-keys) there.

### Which command works where

| Command                                                       | Local | `--url` |
| ------------------------------------------------------------- | ----- | ------- |
| `backup`, `restore`                                           | Yes   | Yes     |
| `users create`                                                | Yes   | Yes     |
| `users recover`, `list`, `deactivate`, `reactivate`, `remove` | Yes   | No      |
| `media regenerate`                                            | Yes   | No      |
| `upgrade`                                                     | Yes   | No      |

The local-only commands need the database or the media storage itself. `users recover` works even when nobody can sign in, for that reason.

## Run in CI

A script has no browser for `tenon login` and no terminal for questions:

- Set `TENON_URL` instead of `--url`.
- Create an API key with the **Backup** permission, and set it as `TENON_API_KEY` instead of `--api-key`. `read` backs up, `update` restores.
- Pass `--yes` to the commands that ask first: `restore`, `upgrade`, `users recover`, `deactivate` and `remove`.

```sh
TENON_URL=https://example.com TENON_API_KEY=$BACKUP_KEY npx tenon backup --out backup.zip
```

A command exits with `0` on success, and with `1` and a message on failure.
