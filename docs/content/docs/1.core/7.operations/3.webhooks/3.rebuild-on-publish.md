---
title: Rebuild on publish
description: Start a new build of a prerendered site when an editor publishes.
---

A prerendered site shows content from its last build. A webhook to the deploy hook of your host starts a new build after each change:

```ts [tenon.config.ts]
webhooks: {
  rebuild: { url: process.env.DEPLOY_HOOK_URL!, debounce: 60 },
},
```

- `debounce` turns a burst of changes into one build. See [Collect changes](/docs/core/operations/webhooks/send-webhooks#collect-changes).
- The host needs a running clock. On Vercel, set up [the clock route](/docs/core/operations/jobs/clock#the-clock-route).
- Editors see drafts only on a page that renders per request. See [Prerendered pages and preview routes](/docs/core/building-your-site/live-preview#prerendered-pages-and-preview-routes).

## Add a deploy button

Some teams publish several changes, then deploy once. An [action](/docs/core/customization/custom-pages-and-actions#actions) adds a **Deploy** button to the admin. The hook URL stays on the server:

```ts [tenon.config.ts]
admin: {
  actions: {
    deploy: {
      label: "Deploy",
      nav: { icon: "rocket" },
      confirm: "Rebuild and publish the live site?",
      run: async () => {
        const response = await fetch(process.env.DEPLOY_HOOK_URL!, { method: "POST" });
        if (!response.ok) throw new Error(`The deploy hook answered ${response.status}`);
        return "Deploy started";
      },
    },
  },
},
```

The action calls the hook at once. It does not wait for the clock.
