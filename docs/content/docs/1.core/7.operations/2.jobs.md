## Define and queue

- `jobs.tasks`, then `cms.jobs.queue()` with a delay or a key.

## Cron

- Entries for recurring tasks.

## The clock

- Which host runs the due jobs on its own, and the clock route for the others.
- UI: table by framework and target; `warning` callout for serverless.

## Retries

- Delivery is at least once, so a task is safe to run twice. The Jobs page shows failures.
