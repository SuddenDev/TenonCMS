Tenon is built to run inside your site. It also works as a headless CMS: another frontend, an app or a service reads the content over the [HTTP API](/docs/core/working-with-content/http-api-and-client). This page explains how that works today, and what does not work yet.

```ts
import { createClient } from "tenoncms/client";

const cms = createClient({ baseUrl: "https://cms.example.com" });
const posts = await cms.find("posts", { limit: 10 });
```

## Two setups

You can use Tenon headless in two ways:

- **Next to your site.** Your Astro, Nuxt or TanStack Start site embeds Tenon as usual. A mobile app, a second site or a script reads from it over HTTP.
- **On its own.** A small Vite app runs only the API and the admin, without pages. Every frontend reads over HTTP. To create one, run `npm create tenoncms@latest` and pick **Standalone**.

The standalone app has one server entry. It serves the admin page and hands every other request to the CMS:

```ts [server.ts]
import html from "#tenon/admin-html";
import cms from "./tenon.config";

const admin = cms.adminPath!;

export default {
  fetch(request: Request) {
    const { pathname } = new URL(request.url);
    if (pathname === admin || pathname.startsWith(`${admin}/`)) {
      return new Response(html, { headers: { "content-type": "text/html; charset=utf-8" } });
    }
    return cms.fetch(request);
  },
};
```

`tenonAdmin()` and Nitro in `vite.config.ts` build the admin and the server. See [Standalone](/docs/guide/frameworks/standalone) for the full project.

## Set the origins

When the frontend and the CMS run on different origins, `tenon.config.ts` needs both:

```ts [tenon.config.ts]
export default defineCms({
  // ...
  site: { url: "https://example.com" },
  auth: { baseURL: "https://cms.example.com" },
});
```

- `site.url` is the public site. The sitemap, `robots.txt` and the URLs from `permalink` use it.
- `auth.baseURL` is the origin of the CMS. Sign-in, invites and every link into the admin use it.

Set `permalink` on a collection to the URL pattern of the frontend, like `/blog/{slug}`. The sitemap, links in rich text and [link fields](/docs/core/content-modeling/fields/link) then point to the frontend's pages. A link field can only link to a collection with a `permalink`.

## Read content

Read in the frontend's server code or at build time:

```ts [src/lib/cms.ts]
import { createClient } from "tenoncms/client";

export const cms = createClient({ baseUrl: "https://cms.example.com" });
```

```ts
const posts = await cms.find("posts", {
  select: { title: true, slug: true, cover: true },
  limit: 10,
});
```

- Published content is public, so reads need no API key.
- A collection that visitors may not read needs an [API key](/docs/core/users-and-access/api-keys) with `read` on it. Fields with `private: true` stay hidden, even from a key.
- A frontend in another language than JavaScript sends plain HTTP requests: `GET https://cms.example.com/_tenon/collections/posts?limit=10` returns JSON. See [Without the client](/docs/core/working-with-content/http-api-and-client#without-the-client).
- The helpers from `tenoncms/client`, like `seoHead()` and `switchTarget()`, work in any JavaScript frontend. `renderRichtext()` from `tenoncms/richtext` turns rich text into HTML.

### Types

The client is typed when the frontend can see the type of your CMS instance:

- **In the same repository**, import only the type. The frontend needs `tenoncms` installed for it.

  ```ts [src/lib/cms.ts]
  import { createClient } from "tenoncms/client";
  import type cms from "../../../cms/tenon.config";

  export const client = createClient<typeof cms>({ baseUrl: "https://cms.example.com" });
  ```

- **In another repository**, the client has no schema. Collection names are plain strings, and documents are loosely typed.

### Browsers on another origin

The API sends no CORS headers, so a browser on another origin cannot call it. Read in the frontend's server or build. If browser code needs content, give the frontend a route that forwards those requests to the CMS. The browser then calls its own origin.

## Images and files

Media URLs in read results are paths on the CMS origin, like `/_tenon/media/files/…`. A frontend on another origin MUST make them absolute:

- **Use a public URL for files.** Set `publicUrl` on `s3()` or `r2()`, or `baseUrl` on `local()`. File URLs then point there.
- **Use a hosted image provider**, like Cloudinary or imgix. Its image URLs are absolute.
- **Or prefix the paths** with the CMS origin, in `src`, `url` and each entry of `srcset`. Images resized by `ipx()` always come from the CMS.

```ts
const absolute = (path: string) => new URL(path, "https://cms.example.com").href;
```

See [Media](/docs/core/content-modeling/media) for storage and image providers.

## Write content

Writes need an API key with the permission, so they run on the frontend's server, never in the browser:

```ts [src/lib/cms.ts]
export const writer = createClient({
  baseUrl: "https://cms.example.com",
  apiKey: process.env.TENON_API_KEY,
});
```

A form on the frontend posts to its own server, which calls `writer.create()`. Every write runs the same validation and hooks as a save in the admin.

A client with a key acts as the key, also for reads. A key needs `read` on every collection and global it reads, even on published content. Keep the public client from [Read content](#read-content) for reads.

## Rebuild on publish

A static frontend shows the content of its last build. A [webhook](/docs/core/operations/webhooks) tells your host to build again when an editor publishes.

## Limits

Tenon is a proof of concept, and the headless setup has gaps:

- **No drafts on another origin.** An API key reads published content only, and an editor's session does not reach another origin. The frontend shows only published content, also inside the live preview.
- **No admin bar.** It needs the editor's session on the site's origin.
- **No generated types.** A frontend in another repository gets an untyped client.
- **No CORS.** Browsers cannot call the API from another origin.

If you need drafts in the preview, the admin bar or types across repositories, run Tenon inside your site instead. See [Add to an existing site](/docs/core/getting-started/existing-site).
