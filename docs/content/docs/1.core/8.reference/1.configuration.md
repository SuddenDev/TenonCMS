title: Configuration
description: Every option of defineCms(), with its type, its default and the page that explains it.
---

`defineCms()` takes one object. Only `database` and `secret` are required. Each entry below links to the page that explains the option in depth. For what `tenon.config.ts` is and how Tenon reads it, see [Configuration](/docs/core/getting-started/configuration).

```ts [tenon.config.ts]
import { defineCms } from "tenoncms";
import { sqlite } from "tenoncms/sqlite";

export default defineCms({
  database: sqlite("./cms.db"),
  secret: process.env.TENON_SECRET!,
  collections: {
    // ...
  },
});
```

## Content

### `collections`

`Record<string, Collection>`. Default: `{}`.

The collections, keyed by name. The name `media` is reserved for the media library. See [Collections and globals](/docs/core/content-modeling/collections-and-globals).

### `globals`

`Record<string, Global>`. Default: `{}`.

The globals, keyed by name. While their [settings](#settings) are on, `general`, `seo` and `translations` are taken. See [Collections and globals](/docs/core/content-modeling/collections-and-globals#globals).

### `blocks`

`Record<string, Block>`. Default: `{}`.

Shared blocks. A [`blocks` field](/docs/core/content-modeling/fields/blocks#nested-blocks) names them by key instead of defining them. A block MAY name itself, so items nest to any depth.

### `presets`

`Preset[]`. Default: `[]`.

Ready-made collections, globals and blocks, like `pagesPreset()`, `menuPreset()` and `stringsPreset()` from `tenoncms/presets`. They merge after your own entries and before the plugins. A duplicate name throws. See [Presets](/docs/core/content-modeling/presets).

### `settings`

`SettingsOptions | false`. Default: `general` and `seo`.

The globals on the admin's **Settings** page. `false` removes all of them. See [Settings](/docs/core/content-modeling/presets/settings).

::field-group

:::field{name="general" type="Global | false"}
Site title, tagline and favicon. A `Global` replaces it, `false` removes it.
:::

:::field{name="seo" type="Global | false"}
Default title, description, image and `noindex`. A `Global` replaces it, `false` removes it.
:::

:::field{name="translations" type="false"}
Added with [`localization`](#localization) when a localized entry has list fields. It holds one switch per entry for keeping the structure of lists the same in every language. `false` removes it.
:::

::

Without media, `general` has no favicon and `seo` has no image. With `localization`, both are localized.

### `localization`

`LocalizationOptions`. Default: off.

Content in several languages. Without it, a `localized` option throws at startup. See [Localization](/docs/core/working-with-content/localization#options).

::field-group

:::field{name="locales" type="string[]" required}
The locale codes. MUST NOT be empty or hold duplicates.
:::

:::field{name="defaultLocale" type="string" required}
The locale of a read without `locale`, and the target of the fallback. MUST be one of `locales`.
:::

:::field{name="fallback" type="boolean"}
A missing value or locale reads as the default locale's. Default: `true`.
:::

:::field{name="routing" type='{ prefix: "except-default" | "always" } | false'}
How URLs carry the locale. `false` leaves routing to your app. Default: `{ prefix: "except-default" }`.
:::

::

### `populate`

`PopulateOptions`. Default: `{}`.

Defaults for reads that resolve relations. See [Relations](/docs/core/content-modeling/relations).

::field-group

:::field{name="depth" type="number"}
How many hops `populate: true` resolves. It also sets the depth of the result types. Default: `2`.
:::

:::field{name="maxDepth" type="number"}
The deepest population a request over HTTP may ask for. The local API has no limit. Default: `5`. `depth` MUST NOT be larger.
:::

::

## Server

### `database`

`DatabaseOptions`. **Required.**

The database. Create it with an adapter:

| Adapter           | Import                | Database                          |
| ----------------- | --------------------- | --------------------------------- |
| `sqlite()`        | `tenoncms/sqlite`     | A SQLite file, with `node:sqlite` |
| `libsql()`        | `tenoncms/libsql`     | libSQL and Turso                  |
| `postgres()`      | `tenoncms/postgres`   | Postgres                          |
| `pglite()`        | `tenoncms/pglite`     | PGlite                            |
| `durableObject()` | `tenoncms/cloudflare` | SQLite in a Durable Object        |

A missing URL or path fails at startup. See [Databases](/docs/guide/databases-and-storage/databases).

### `secret`

`string`. **Required.**

Signs sessions. It MUST have at least 32 characters, also in development. Read it from an environment variable. See [Configuration](/docs/core/getting-started/configuration#environment-variables).

### `site`

`SiteOptions`. Default: none.

::field-group

:::field{name="url" type="string"}
The public origin of your site, like `https://example.com`. The sitemap, `robots.txt` and preview URLs use it. It is also the default of `auth.baseURL` and of the CORS origin. MUST be an http(s) origin without a path. Default: the origin of each request.
:::

:::field{name="name" type="string"}
The name of the site. The admin, the admin bar, emails and passkeys show it. Default: `"tenoncms"`.
:::

::

See [Configuration](/docs/core/getting-started/configuration#site-url) and [Branding](/docs/core/customization/admin#branding).

### `auth`

`AuthOptions`. Default: `{}`.

The options of [better-auth](https://www.better-auth.com/docs/reference/options), passed through. Tenon sets `database`, `secret` and `basePath` (`/_tenon/auth`) itself, and the models `user`, `session`, `account` and `verification` MUST NOT set `modelName`. See [Authentication](/docs/core/users-and-access/authentication#auth-options).

Tenon changes these defaults:

| Key                                                                             | Default in Tenon                                                                       |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `baseURL`                                                                       | `site.url`, then better-auth's environment variables, then localhost in development    |
| `appName`                                                                       | `site.name`                                                                            |
| `emailAndPassword.enabled`                                                      | `true`                                                                                 |
| `emailAndPassword.sendResetPassword`, `emailVerification.sendVerificationEmail` | The templates of [`email`](#email), when it is set                                     |
| `rateLimit.storage`                                                             | `"database"`                                                                           |
| `user.additionalFields`                                                         | Also has `language` and `timezone`                                                     |
| `plugins`                                                                       | Tenon adds `admin()`, `apiKey()`, `bearer()` and a few of its own, unless you add them |

The first user always gets the role `admin`. At least one sign-in method MUST be on.

### `roles`

`Record<string, RoleOptions>`. Default: only `admin` and `editor`.

More roles for [access rules](/docs/core/users-and-access/access-control#users-and-roles). A name MUST use `a-z`, `0-9` and `-`, and MUST NOT be `admin` or `editor`.

::field-group

:::field{name="label" type="Text"}
The name in the admin. Default: the key.
:::

:::field{name="description" type="Text"}
Shown where an admin picks a role.
:::

::

### `email`

`EmailOptions`. Default: off. Without it, `cms.email.send()` throws. See [Email](/docs/core/operations/email).

::field-group

:::field{name="adapter" type="EmailAdapter" required}
The transport: [`smtp()`](/docs/core/operations/email/smtp), [`cloudflareEmail()`](/docs/core/operations/email/cloudflare) or a [custom adapter](/docs/core/operations/email/custom-adapter).
:::

:::field{name="from" type="string" required}
The sender of every message, like `My Site <hello@example.com>`.
:::

:::field{name="templates" type="Partial<EmailTemplates>"}
Replacements for `resetPassword`, `verifyEmail`, `invite`, `signInLink`, `magicLink` and `emailOtp`. See [Change the built-in emails](/docs/core/operations/email#change-the-built-in-emails).
:::

::

### `media`

`MediaOptions | boolean`. Default: local files in `.uploads`.

The media library, and with it `image` and `file` fields. `false` turns it off. On Cloudflare Workers, or in a read-only folder, the default is off and `true` throws. See [Media](/docs/core/content-modeling/media).

::field-group

:::field{name="storage" type="Storage" required}
Where files go: `local()`, `s3()`, `r2()` from `tenoncms/media/*`, or your own. See [Media storage](/docs/guide/databases-and-storage/media-storage).
:::

:::field{name="maxSize" type="number"}
The largest file, in bytes. Default: `100 * 1024 ** 2` (100 MB).
:::

:::field{name="accept" type="string[]"}
The allowed MIME types. `image/*` works. Default: all.
:::

:::field{name="images" type="ImagesOptions | false"}
Responsive image variants. Default: `false`. See [Responsive images](/docs/core/content-modeling/media#responsive-images).

| Key        | Type                        | Default                              |
| ---------- | --------------------------- | ------------------------------------ |
| `provider` | `ImageProvider`, required   |                                      |
| `format`   | `string`                    | `"webp"`                             |
| `quality`  | `number`                    | `85`                                 |
| `sizes`    | `number[]`                  | `[320, 640, 1024, 1536, 1920]`       |
| `presets`  | `Record<string, Modifiers>` | `{}`                                 |
| `maxSize`  | `number`, in bytes          | 50 MB. Bigger images get no variants |

:::

:::field{name="access" type="Access"}
The access rules of the library. `read` also guards the file and image URLs. Default: everyone reads, signed-in users write.
:::

:::field{name="hooks" type="MediaHooks"}
`beforeUpload`, `afterUpload`, `beforeChange`, `afterChange`, `beforeMove`, `afterMove`, `beforeDelete` and `afterDelete`.
:::

::

### `cors`

`CorsOptions`. Default: off.

CORS for pages on another origin, with the options of Hono's `cors()`. Your keys replace the defaults key by key: `origin` is `site.url`, `credentials` is `true`, `allowMethods` is `["GET", "POST"]` and `allowHeaders` is `["content-type"]`. It covers the read, preview, localization and admin bar routes. It needs `origin` or `site.url`. See [Headless](/docs/core/working-with-content/headless#allow-more-origins).

## Site output

### `sitemap`

`SitemapOptions | false`. Default: on.

Serves `/sitemap.xml` with the published documents of every collection that has a `permalink`. `entries: ({ cms, entries }) => entries` adds, drops or changes entries. `false` turns it off. See [Sitemap and robots.txt](/docs/core/building-your-site/pages-and-seo#sitemap-and-robotstxt).

### `robots`

`RobotsOptions | false`. Default: on.

Serves `/robots.txt`. By default it allows `/` and `/_tenon/media/`, disallows `/_tenon/`, and links the sitemap. With the SEO setting `noindex`, it disallows `/`. `rules: ({ cms, rules }) => rules` changes the groups. `false` turns it off.

## Automation

### `jobs`

`JobsOptions`. Default: none. See [Jobs](/docs/core/operations/jobs).

::field-group

:::field{name="tasks" type="Record<string, Task>"}
Tasks from `defineTask()`, by name. A name MUST NOT start with `tenon:`.
:::

:::field{name="scheduledTasks" type="Record<string, string[]>"}
Cron patterns with five fields, mapped to task names. See [Recurring jobs](/docs/core/operations/jobs/recurring-jobs).
:::

:::field{name="secret" type="string"}
Opens the [clock route](/docs/core/operations/jobs/clock#the-clock-route) for `Authorization: Bearer <secret>`. Without it, the route does not exist.
:::

::

### `webhooks`

`Record<string, Webhook>`. Default: `{}`.

Outgoing webhooks, by name: `url`, `collections`, `globals`, `events`, `payload`, `debounce`, `secret` and `headers`. See [Send webhooks](/docs/core/operations/webhooks/send-webhooks#options).

### `hooks`

`RootHooks`. Default: `{}`.

Hooks for every collection and global. They run after the hooks of the entry and of the plugins. See [Hooks](/docs/core/working-with-content/hooks).

## Lifecycle

All four take one function. See [Lifecycle hooks](/docs/core/operations/lifecycle-hooks).

| Option        | Runs                                                              |
| ------------- | ----------------------------------------------------------------- |
| `seed`        | Once, on a database without documents and globals                 |
| `onInit`      | On every start, after `seed`, before the first request            |
| `afterImport` | After `cms.import()` commits                                      |
| `afterError`  | After an unexpected error in a request, a job, `seed` or `onInit` |

## Admin and plugins

### `admin`

`AdminOptions | false`. Default: the admin at `/admin`.

`false` serves no admin, no admin bar and no device login for the CLI. See [Admin](/docs/core/customization/admin).

::field-group

:::field{name="path" type="string"}
Where the admin opens. Letters, digits, `-` and `_`. MUST NOT be `/` or start with `/_tenon`. Default: `"/admin"`.
:::

:::field{name="logo" type="Themed | { header, login }"}
The wide logo. Default: the icon and the site name.
:::

:::field{name="icon" type="Themed"}
The square icon of the collapsed sidebar.
:::

:::field{name="favicon" type="Themed"}
Default: `icon`, then the `favicon` of your site, then Tenon's icon.
:::

:::field{name="media" type="{ label, nav, pageHeader }"}
The label and the menu place of the media library.
:::

:::field{name="fields" type="Record<string, FieldRegistration>"}
Inputs for `custom:<key>` fields. See [Custom fields](/docs/core/customization/custom-fields).
:::

:::field{name="pages" type="Record<string, PageRegistration>"}
Pages of your own. See [Custom pages and actions](/docs/core/customization/custom-pages-and-actions).
:::

:::field{name="actions" type="Record<string, ActionRegistration>"}
Buttons that run code on the server. Default access: admins. See [Actions](/docs/core/customization/custom-pages-and-actions#actions).
:::

:::field{name="adminBar" type="{ position, items } | false"}
The bar on your site for signed-in editors. Default position: `"bottom-center"`. See [Admin bar](/docs/core/customization/admin#admin-bar).
:::

::

### `richtext`

`{ extensions?: Record<string, RichtextRegistration> }`. Default: `{}`.

Tiptap extensions for `richtext` fields, keyed by the name that a field's `allowed` lists. Each has a `schema` for the server and a `client` from `clientRef()`. See [Rich text extensions](/docs/core/customization/rich-text-extensions).

### `plugins`

`Plugin[]`. Default: `[]`.

Plugins from `definePlugin()`. They merge in list order, before your own hooks. See [Plugins](/docs/core/customization/plugins).

| Key                                           | What it adds                                             |
| --------------------------------------------- | -------------------------------------------------------- |
| `name`                                        | Required. Prefixes the routes and the task names         |
| `collections`, `globals`                      | Entries, like your own                                   |
| `hooks`, `mediaHooks`                         | Hooks for every entry, and for the media library         |
| `routes`                                      | Routes under `/_tenon/<name>` that need a session        |
| `publicRoutes`                                | Routes under `/_tenon/<name>` without a session          |
| `middleware`, `publicMiddleware`              | Middleware for requests with a session, or for all       |
| `jobs`                                        | `tasks` and `scheduledTasks`. Names start with `<name>:` |
| `richtext`, `admin`                           | Editor extensions and admin parts                        |
| `seed`, `onInit`, `afterImport`, `afterError` | Lifecycle hooks                                          |

## Startup checks

`defineCms()` checks the config when it loads, and throws before the first request.

- `secret`, `site.url`, `cors`, `database` and `media.storage` are checked together. The error `tenoncms: invalid config` lists every problem among them.
- Every other check throws on its own problem, like an unknown role in an access rule, a cron pattern without five fields or a webhook URL that is not http(s).
