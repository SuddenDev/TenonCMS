## How sign-in works

- The first user signs up and is the admin. Everyone else joins by invite.
- Auth builds on better-auth. Its options pass through `auth`.

## Sign-in methods

- Password, passkey, magic link, email code: what turns each one on.
- UI: table; one config sample per method in `tabs`.

## Recovery

- Reset by email. `tenon users recover` when nobody can sign in.

## Auth options

- `baseURL` and `allowedHosts`, sessions, rate limits, own better-auth plugins.
