A plugin bundles a feature into one import: collections and globals, hooks, API routes and admin pieces. You add it once in `tenon.config.ts`, with nothing else to wire up. This page shows how to use a plugin and the plugins that come with Tenon.

## Use a plugin

List plugins in `plugins`:

```ts [tenon.config.ts]
import { defineCms } from "tenoncms";
import { RedirectsPlugin } from "tenoncms/plugins/redirects";

export default defineCms({
  // ...
  plugins: [RedirectsPlugin()],
});
```

A plugin can add:

- collections and globals. They are typed like yours, so `cms.find("redirects")` works.
- hooks for every collection, and [lifecycle hooks](/docs/core/operations/lifecycle-hooks) like `seed`.
- API routes under `/_tenon/<plugin name>`, and middleware for the API.
- [jobs](/docs/core/operations/jobs) and their schedules.
- [rich text extensions](/docs/core/customization/rich-text-extensions).
- [fields](/docs/core/customization/custom-fields), [pages and actions](/docs/core/customization/custom-pages-and-actions), and admin bar items.

A plugin's additions come before yours. Its hooks run before your root hooks, and its lifecycle hooks before yours. A collection, global, field or page name that you and a plugin both use stops the server at startup.

## Redirects

`RedirectsPlugin()` adds a **Redirects** collection to the admin. When the path of a page changes, it creates a redirect from the old path:

```ts [tenon.config.ts]
plugins: [RedirectsPlugin({ collections: ["pages"], field: "path", locales: ["en", "de"] })],
```

::field-group
:::field{name="collections" type="string[]"}
The collections whose path changes create a redirect. Default `["pages"]`.
:::

:::field{name="field" type="string"}
The path field in those collections. Default `"path"`.
:::

:::field{name="locales" type="string[]"}
The languages to pick for a redirect. Without it, the language is a text input. An empty language applies to all.
:::
::

- A redirect has `from`, `to`, `permanent` (`301`, the default, or `302`) and `locale`.
- Redirects that pointed to the old path follow the move, so there is never more than one hop.
- **Redirect Tools** in the admin tests a path and imports many redirects at once.

### Resolve redirects on your site

The plugin stores redirects. Your site follows them in a middleware, before any page renders. `resolveRedirect()` returns the target and the status, or `undefined`:

::code-group{sync="framework"}

```ts [Astro]
// src/middleware.ts
import { defineMiddleware } from "astro:middleware";
import { resolveRedirect } from "tenoncms/plugins/redirects";
import cms from "../tenon.config";

export const onRequest = defineMiddleware(async (context, next) => {
  const redirect = await resolveRedirect(cms, context.url.pathname);
  return redirect ? context.redirect(redirect.to, redirect.status) : next();
});
```

```ts [Nuxt]
// server/middleware/redirects.ts
import cms from "#tenon/config";
import { resolveRedirect } from "tenoncms/plugins/redirects";

export default defineEventHandler(async (event) => {
  const redirect = await resolveRedirect(cms, getRequestURL(event).pathname);
  if (redirect) return sendRedirect(event, redirect.to, redirect.status);
});
```

```ts [TanStack Start]
// src/start.ts
import { createMiddleware, createStart } from "@tanstack/react-start";
import { resolveRedirect } from "tenoncms/plugins/redirects";
import cms from "../tenon.config";

const redirects = createMiddleware().server(async ({ request, next }) => {
  const redirect = await resolveRedirect(cms, new URL(request.url).pathname);
  if (redirect) return Response.redirect(new URL(redirect.to, request.url), redirect.status);
  return next();
});

export const startInstance = createStart(() => ({ requestMiddleware: [redirects] }));
```

::

- With languages, pass the page's language as the third argument: `resolveRedirect(cms, path, "de")`. A redirect for that language wins over one for all.
- A site on another origin asks `GET /_tenon/redirects/lookup?path=/old-page`. It answers `{ to, status }`, or `404`. Add `&locale=de` for a language.

## The example plugin

`ExamplePlugin()` from `tenoncms/plugins/example` is not a feature. It is code to copy when you write your own plugin. It adds a `quotes` collection with a custom field, a settings global, a scheduled job, API routes, admin pages, admin bar items and a rich text extension.

Its browser code exists in plain DOM, Vue and React. `renderer: "html" | "vue" | "react"` picks one. Its source is in the Tenon repository, under `packages/plugins/src/example/`.

## Write your own

A plugin is an object from `definePlugin()`. Use one to share a feature between projects, or to keep a feature of your own site in one place. See [Write a plugin](/docs/guide/recipes/write-a-plugin).
