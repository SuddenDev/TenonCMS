## What is Tenon?

Tenon is a CMS-as-a-package you add to your app. It is made for [Vite](https://vite.dev)-based apps and works best there, but any server that speaks `Request` and `Response` can run it. It adds the admin and an HTTP API as routes of your app. Your server code reads content with a direct function call, without HTTP. You can extend it with your own fields, pages and plugins, or run it standalone as a headless CMS.

## Why Tenon?

Most headless CMSs run as a second service, and your site calls them over HTTP. That works, but for small and medium sites it is often more than you need. A hosted CMS locks you and your content to a vendor. A self-hosted one is another service to deploy, secure and keep in sync.

Tenon keeps the CMS in your app. You describe your content in TypeScript:

```ts [collections/posts.ts]
import { defineCollection } from "tenoncms";

export const posts = defineCollection({
  titleField: "title",
  fields: {
    title: { type: "text", required: true },
    slug: { type: "slug", from: "title", unique: true },
    body: { type: "richtext" },
  },
});
```

The types flow into your pages. `find()` knows the fields of `posts`, so a typo in a field name fails the type check:

```ts [server.ts]
import cms from "./tenon.config";

const posts = await cms.find("posts", { where: { slug: "hello-world" } });
console.log(posts[0]?.title);
```

## Runs where your app runs

Tenon deploys with your app, wherever it runs:

- [**Node**](/docs/guide/deployment/node): any server or container, with SQLite, Postgres or PGlite
- [**Vercel**](/docs/guide/deployment/vercel): serverless functions with Turso or Postgres
- [**Cloudflare**](/docs/guide/deployment/cloudflare): Workers with a Durable Object database and R2

## Key features

- [**Content modeling**](/docs/core/content-modeling/collections-and-globals): Collections, fields, relations, blocks and media, all defined in TypeScript
- [**Typed local API**](/docs/core/working-with-content/reading): Read content from server code with a direct function call
- [**HTTP API**](/docs/core/working-with-content/http-api-and-client): An HTTP API with a typed browser client
- [**Localization**](/docs/core/working-with-content/localization): Content in several languages, with fallbacks
- [**Pages and SEO**](/docs/core/building-your-site/pages-and-seo): Nested pages, SEO tags and a sitemap
- [**Live preview**](/docs/core/building-your-site/live-preview): Editors see drafts on the real page
- [**Users and access**](/docs/core/users-and-access/authentication): Password, passkey or email sign-in, with roles and access rules
- [**Plugins**](/docs/core/customization/plugins): Add your own fields, admin pages and features
- [**Operations**](/docs/core/operations/email): Email, background jobs, webhooks and backups

## Limits and status

- Tenon needs a server runtime. The admin and the API are server routes, so a purely static host cannot run them. Pages can still be prerendered or you use Tenon as a [standalone headless CMS](/docs/guide/frameworks/standalone).
- Tenon is built for and with Vite. Nonetheless it should be possible to integrate it with [other frameworks](/docs/guide/frameworks/other-frameworks). With a Vite-based framework, the integration serves the admin, runs background jobs and loads your custom admin code. Without Vite, you route the API, mount the admin and run jobs yourself. Currently untested though.
