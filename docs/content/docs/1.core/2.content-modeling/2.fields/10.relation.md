A `relation` stores the id of another document, like the author of a post. A `join` is the other side: it lists the documents whose relation points here, like the posts of an author.

:field-preview{name="relation"}

## Example

```ts [cms/collections/posts.ts]
export const posts = defineCollection({
  fields: {
    title: { type: "text", required: true },
    author: { type: "relation", collection: "authors" },
    tags: { type: "relation", collection: "tags", many: true },
  },
});
```

A read loads the related documents in place of the ids:

```ts
const post = await cms.findOne("posts", { where: { slug } });
post?.author?.name; // string
post?.tags?.map((tag) => tag.title);

const raw = await cms.findOne("posts", { where: { slug }, populate: false });
raw?.author; // string, the id
```

### Render it

::code-group{sync="framework"}

```astro [Astro]
<p>By {post.author?.name ?? "Unknown"}</p>
<ul>
  {post.tags?.map((tag) => <li>{tag.title}</li>)}
</ul>
```

```vue [Nuxt]
<template>
  <p>By {{ post.author?.name ?? "Unknown" }}</p>
  <ul>
    <li v-for="tag in post.tags" :key="tag.id">{{ tag.title }}</li>
  </ul>
</template>
```

```tsx [TanStack Start]
<>
  <p>By {post.author?.name ?? "Unknown"}</p>
  <ul>
    {post.tags?.map((tag) => (
      <li key={tag.id}>{tag.title}</li>
    ))}
  </ul>
</>
```

::

How deep a read loads, and how to keep the loaded documents small, is in [Relations](/docs/core/content-modeling/relations#populate).

- Each write checks that every id exists. A document cannot point to itself.
- A `many` relation keeps its order and rejects duplicates.
- A `relation` works at the top level, in groups and in list items, in collections and globals. It can only point to collections.
- A typo in `collection` is a type error in `tenon.config.ts`.

You can filter by a single top-level relation: `cms.find("posts", { where: { author: id } })`. Filters do not accept `many` relations, relations in groups or joins.

## Join

A `join` stores nothing. It lists the documents of `collection` whose relation `on` points to this document:

```ts [cms/collections/authors.ts]
export const authors = defineCollection({
  titleField: "name",
  fields: {
    name: { type: "text", required: true },
    posts: { type: "join", collection: "posts", on: "author" },
  },
});
```

:field-preview{name="join"}

A read loads a join only when you name it:

```ts
const author = await cms.findById("authors", id, { populate: { posts: true } });
author?.posts?.map((post) => post.title);
```

::code-group{sync="framework"}

```astro [Astro]
<h2>Posts by {author.name}</h2>
<ul>
  {author.posts?.map((post) => (
    <li><a href={`/posts/${post.slug}`}>{post.title}</a></li>
  ))}
</ul>
```

```vue [Nuxt]
<template>
  <h2>Posts by {{ author.name }}</h2>
  <ul>
    <li v-for="post in author.posts" :key="post.id">
      <NuxtLink :to="`/posts/${post.slug}`">{{ post.title }}</NuxtLink>
    </li>
  </ul>
</template>
```

```tsx [TanStack Start]
<>
  <h2>Posts by {author.name}</h2>
  <ul>
    {author.posts?.map((post) => (
      <li key={post.id}>
        <a href={`/posts/${post.slug}`}>{post.title}</a>
      </li>
    ))}
  </ul>
</>
```

::

- A `join` works only at the top level of a collection.
- `on` can name a relation inside a group, like `seo.image`.
- `required`, `default`, `hidden` and `private` do not apply, because a join stores nothing.

## Options

::field-group
:::field{name="type" type='"relation"' required}
:::

:::field{name="collection" type="string" required}
The collection the ids point to. It can be the collection that holds the field, like a parent page.
:::

:::field{name="many" type="boolean"}
Store a list of ids instead of one. With `required`, at least one. Default `false`.
:::

:::field{name="select" type="Record<string, true | object>"}
The fields a loaded document keeps, like `{ name: true, avatar: true }`. See [Keep related documents small](/docs/core/content-modeling/relations#keep-related-documents-small).
:::

:::field{name="onDelete" type='"set-null" | "restrict" | "cascade"'}
What happens when the related document is deleted. Default `"restrict"` for a `required` relation, otherwise `"set-null"`. See [When a document is deleted](/docs/core/content-modeling/relations#when-a-document-is-deleted).
:::
::

The options of a `join`:

::field-group
:::field{name="type" type='"join"' required}
:::

:::field{name="collection" type="string" required}
The collection whose documents point here.
:::

:::field{name="on" type="string" required}
The relation field in `collection` that points here, like `author` or `seo.image`.
:::
::
