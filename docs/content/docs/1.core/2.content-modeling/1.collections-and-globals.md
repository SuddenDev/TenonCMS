You describe your content in TypeScript. A **collection** is a list of documents with the same fields, like posts. A **global** is one document per name, like the site settings. Both are plain objects, and the types of your documents come from them.

## Collections

A collection holds many documents that share one set of fields. Define it with `defineCollection()`, usually in its own file:

```ts [cms/collections/posts.ts]
import { defineCollection } from "tenoncms";

export const posts = defineCollection({
  label: "Posts",
  titleField: "title",
  permalink: "/posts/{slug}",
  fields: {
    title: { type: "text", required: true },
    slug: { type: "slug", from: "title", unique: true },
    date: { type: "date" },
    body: { type: "richtext" },
  },
});
```

Register it in `tenon.config.ts`. The key is the name you read it by:

```ts [tenon.config.ts]
import { defineCms } from "tenoncms";
import { sqlite } from "tenoncms/sqlite";
import { posts } from "./cms/collections/posts";

export default defineCms({
  database: sqlite("./cms.db"),
  secret: process.env.TENON_SECRET!,
  collections: { posts },
});
```

```ts
const all = await cms.find("posts");
const one = await cms.findOne("posts", { where: { slug: "hello-world" } });
```

::tip
While these examples show that collections should be in there own files, they don't have to be. `defineCollection()` only adds types. You can also write the object straight into `collections`.
::

::warning
Every document also gets `id`, `createdAt`, `updatedAt`, `publishedAt` and `hasDraft`. Do not use these names for your own fields.
::

## Globals

A global is a single document, such as a footer, a cookie banner or contact details. It has no list and no `id` to look up. Define it with `defineGlobal()`:

```ts [cms/globals/footer.ts]
import { defineGlobal } from "tenoncms";

export const footer = defineGlobal({
  label: "Footer",
  fields: {
    copyright: { type: "text" },
    email: { type: "text" },
  },
});
```

```ts [tenon.config.ts]
export default defineCms({
  // ...
  globals: { footer },
});
```

```ts
const footer = await cms.getGlobal("footer");
```

A global that was never saved reads as `{}`. Handle missing values in your templates.

::note
Tenon adds two globals on its own: `general` (site title, tagline, favicon) and `seo` (title template, description, share image). They live on the admin's **Settings** page. See [Pages and SEO](/docs/core/building-your-site/pages-and-seo#site-settings).
::

## Options

Collections and globals take the same options, except where the table says otherwise.

::field-group
:::field{name="fields" type="Fields" required}
The fields of each document. See [Fields](/docs/core/content-modeling/fields).
:::

:::field{name="label" type="string | { en, de, … }"}
The name in the admin. Defaults to the key. Pass an object to translate it.
:::

:::field{name="description" type="string | { en, de, … }"}
Short text under the name, above the form and on the Settings page.
:::

:::field{name="titleField" type="string" :badges='[{"label":"Collections only","color":"callout"}]'}
The field the admin shows in lists and pickers. Defaults to the first field.
:::

:::field{name="permalink" type="string"}
If you want to serve a collection through a route, like `/posts/{slug}` you have to set the permalink. E.g. `{slug}` is a field placeholder on that document. You can also choose another field or even multiple. The sitemap, links and the live preview use it.
:::

:::field{name="localized" type="boolean"}
Store the values per language. Default `false`. See [Localization](/docs/core/working-with-content/localization).
:::

:::field{name="drafts" type="boolean"}
Keep a draft next to the published version. Default `true`.
:::

:::field{name="schedule" type="boolean"}
Editors can plan a publish or unpublish for later. Needs `drafts`. Default `false`.
:::

:::field{name="access" type="Access"}
Who can read, create, update and delete. By default, everyone reads published content and signed-in users do the rest. See [Access control](/docs/core/users-and-access/access-control).
:::

:::field{name="hooks" type="Hooks"}
Functions that run on reads, writes and deletes. See [Hooks](/docs/core/working-with-content/hooks).
:::

:::field{name="nav" type="{ display, group, icon, order }"}
Where the entry shows in the admin. `icon` is a [Lucide](https://lucide.dev/icons) name and `display` can be

- `"content"` (the sidebar, default)
- `"settings"` (the built-in Settings page)
- `"main"` (the top bar)
- `"none"` (don't show at all)
  :::

:::field{name="tabs" type="Record<string, { label, icon }>" :badges='[{"label":"Admin only","color":"note"}]'}
UI Tabs in the admin form. A field picks its tab with `tab: "name"`. Fields without a `tab` show above the tabs.
:::

:::field{name="fieldsets" type="Record<string, { label, description, collapsible }>" :badges='[{"label":"Admin only","color":"note"}]'}
Boxes around fields in the admin form. A field picks its box with `fieldset: "name"`.
:::

:::field{name="sitemap" type="boolean" :badges='[{"label":"Collections only","color":"callout"}]'}
List the documents in `/sitemap.xml`. Needs a `permalink`. Default `true`.
:::
::

`tabs` and `fieldsets` change only the admin. The stored document keeps its shape:

```ts
export const posts = defineCollection({
  tabs: {
    content: { label: "Content", icon: "file-text" },
    meta: { label: "Meta", icon: "tag" },
  },
  fields: {
    title: { type: "text", required: true, tab: "content" },
    body: { type: "richtext", tab: "content" },
    date: { type: "date", tab: "meta" },
  },
});
```

## Presets

Most sites need the same few things: pages with nested URLs, a navigation menu and SEO. Presets give you these as ready-made collections and globals from `tenoncms/presets`. See [Presets](/docs/core/content-modeling/presets).

## Types

The schema is the type. You write no interfaces, and reads return typed documents:

```ts
const post = await cms.findOne("posts", { where: { slug } });
post?.title; // string
post?.date; // string | null | undefined

cms.find("postz"); // type error: unknown collection
cms.find("posts", { where: { titel: "Hi" } }); // type error: unknown field
```

- A `required` field is never `null` or missing.
- `select` and `populate` change the result type. See [Reading](/docs/core/working-with-content/reading).
- The same types reach the browser through `createClient()`. See [HTTP API and client](/docs/core/working-with-content/http-api-and-client).

`defineCms()` also checks the schema when it starts. A relation to an unknown collection or a condition on an unknown field stops the server with an error that lists every problem.
